# Improve

围绕约定目标改进已有成果。将每个候选与已接受版本比较，再决定保留、撤回或暂列待定。

遵循宿主的任务流程、工具、模型选择及授权。根据实际对象选择专业方法。

## 流程

### 1 明确约定

读取已有对象、任务要求及现有结果。确定：

- 主要改进目标及允许修改的范围。
- 必须保持的行为、事实、接口或其他属性。
- 比较结果的方法，以及什么变化算有意义的改善。
- 停止条件，包括已约定的尝试次数、时间或资源限制。

改动 Skill、提示词或其他 Agent 指引时，先读取 [Agent 指引评估](./references/agent-artifacts.md)，再选择比较方法。

可测量的结果使用测量，具体要求使用行为检查，需要判断的质量使用有依据的比较。指出成果中支持判断的具体内容。将必须保持的属性与改进目标分别处理。

从现有材料和环境中查明事实。仍需选择的重要偏好或取舍交给用户。已有约定能够回答这些问题时，直接沿用。

能够判断候选是否值得保留，并明确允许的范围及停止条件后，进入下一步。

### 2 建立基线

标识最初基线及当前已接受版本。保存比较和恢复本次工作所涉及状态需要的信息。

按约定方法观察基线，同时检查必须保持的属性。记录版本、输入、评价方法及相关条件。条件一致时复用已有结果。

检查评价方法能否区分重要的结果。优先使用现有检查和工具，补充比较所需的最少测量能力。原版已经满足目标时，保留原版。

起点可识别、可恢复，并有可比较的观察依据后，进入下一步。

### 3 选择假说

读取既往尝试，根据当前对象和证据提出下一条假说。说明改动、预期起作用的机制，以及哪些观察会支持或否定它。

每轮围绕一个可以解释的假说。一条假说可以需要协调修改多个文件。重新尝试既往方向时，说明哪些条件发生了变化，使它值得再试。

候选已足够明确，可以按约定实施和评价后，进入下一步。

### 4 比较候选

在授权范围内完成改动，采用适合对象的专业方法。编写 Agent 指引时读取 `writing-for-agents`。

使用相同方法及相关条件，比较候选和当前已接受版本。同时检查必须保持的属性及预期改善。直接检查实际成果和结果，委派的工作也按此处理。

通过足以支持结论的重复或交错观察，处理噪声及顺序影响。保留实际条件。评价方法有误时，记录问题，修正方法，再用修正后的依据评价受影响的基线及候选。保留原始记录。

采用宿主允许的执行方式。并行尝试需要独立的候选状态。即使各部分分别有效，组合后也要评价其整体结果再决定接受。

候选、比较条件、观察结果及属性检查能够对应到同一次尝试后，进入下一步。

### 5 处理结果

- **保留**：约定目标得到改善，必须保持的属性满足要求。将候选设为已接受版本。
- **撤回**：候选不符合约定。恢复本轮改动，保留其他工作及原始证据。
- **待定**：证据不足或相互矛盾。保存候选及不确定性，继续使用已接受版本。说明哪些证据能够解决这个判断。

简化已经列入目标，且相关行为保持时，结果持平但成果更简单也可以算改善。在评判本轮尝试前确定这一标准。

使用任务已有的记录格式，保存假说、改动对象、对照版本、相关条件、前后证据、属性检查及决定。未采用的尝试也能为下一次选择提供依据。

完成本轮判断后再开始下一轮。进展停滞时，重新检查问题解释、评价方法及可用的改法，再决定下一次尝试是否值得。

### 6 结束

目标及确认要求已经满足、基线原本就满足目标、有价值的可行假说已检查完、达到约定限制，或具体阻塞需要决策时，结束改进。

保持约定的成功标准。目标变化作为单独的决定处理，并建立新的比较依据。

对照最初基线，说明最终保留的结果、支持证据及其条件、重要取舍和停止原因。说明目标是否达到，或仍有哪些差距。保留原始成果也是有效结果。

审查、提交、合并、发布及安装遵循所在工作流和授权。
