# 表达性质

表达或审查行为应保持的承诺时读取。用读者的语言写出承诺，给出需求来源，再选择语义合适的表达。

## 状态不变量

状态谓词描述单个状态。不变量要求它在初态及选定规范的每个可达状态成立。类型不变量还可以发现模型越出预期取值域的问题。

[保存示例](../examples/AsyncSave.tla)使用：

```tla
SavedTruth == saved => acknowledged = current
```

承诺是“显示已保存时，已确认版本等于当前版本”。模型需要两个版本及显示值。在 TLC 配置中用 `INVARIANT SavedTruth` 注册。

## 动作性质

动作谓词描述一步前后状态的关系。未加撇的变量代表前态，加撇的变量代表后态。余额改变多少的规则需要前后值及操作金额。

要求确认版本始终不倒退时，可以用时序表达约束每一步：

```tla
AckNeverDecreases == [][acknowledged' >= acknowledged]_vars
```

这项时序公式使用 `PROPERTY AckNeverDecreases`。说明一个业务操作对应一个还是多个模型动作。约束完整操作的性质可能需要操作身份及中间状态，按每个实现微步施加限制需要相应依据。

## 安全性

安全性要求坏事始终不发生。违反具有有限的坏前缀。状态不变量能表达许多安全性要求。有些要求需要历史，例如“已释放的租约再也不会写入”。当前状态丢失了检测违反所需的事实时，增加有含义的历史或持有者代次。解释新增状态，并在相关动作中更新。

诊断失败时保持需求不变。期望承诺确实改变后，凭相应依据修订。检查失败可能暴露模型错误、实现错误或两者差异。

## 活性

活性要求在给定条件下最终取得进展。在 TLA+ 中，`[]P` 表示始终，`<>P` 表示最终，`P ~> Q` 表示每次 P 成立后最终会出现 Q。

保存示例使用：

```tla
PendingEventuallySaved ==
    (acknowledged < current) ~>
        (acknowledged = current /\ saved /\ inflight = NoRequest)
```

它承诺出现待保存内容后，最终获得确认并如实显示已保存。达到该条件前允许继续编辑。示例最多允许 `MaxVersion` 次编辑、可靠确认及单个在途请求。公平规范要求提交和确认取得进展。持续无限编辑时，这项追上当前版本的承诺需要不同假设或按版本表达的性质。

测试中的有限超时需要应用时限契约。模型中的最终发生本身没有实际耗时上界。活性反例是无限行为，通常用有限前缀加重复循环或持续停顿后缀表达。

## 公平性

`WF_vars(A)` 要求持续可执行的非停顿 A 步最终执行。`SF_vars(A)` 还覆盖无限次获得执行机会的动作。说明调度器或环境为何提供选定条件。

保存示例的 `Spec` 为 `Submit` 和 `Ack` 采用弱公平。编辑停止后，只要请求槽为空，待保存工作就使提交持续可执行。在途请求使确认持续可执行。有限编辑配合这些假设，允许系统追上当前版本。

`UnfairSpec` 保留相同初态、转移和性质，移除这些调度承诺。它允许编辑后始终停顿，持续留有待保存内容。比较 [safe.cfg](../examples/safe.cfg) 和 [unfair.cfg](../examples/unfair.cfg)。这是示例要展示的活性差别。

将公平性施加到系统实际保证取得进展的动作。对宽泛析取施加公平性，可能允许一个分支永远执行，另一个始终饥饿。强公平可以排除真实存在的饥饿，使用它需要相应保证。

## 死锁

TLC 的死锁检查判断模型下一状态关系是否提供后继。它独立于活性检查。时序规范中 `[Next]_vars` 允许的停顿仍能形成时序行为，TLC 对可执行后继的检查可以报告 `Next` 中的死锁。

按语义区分无工作状态：

- 合法结束或静止状态可以有受守卫限制的 `UNCHANGED vars` 动作。
- 等待输入需要环境允许的事件动作，或显式说明外部输入在当前检查边界之外。
- 非预期的非终态没有任何可执行后继时，形成死锁发现。

保存示例只在版本相等且请求槽为空时启用 `Quiescent`。显示真实性单独检查。全局无条件保持动作会让每个状态都有后继，掩盖意外死锁。保持死锁检查开启，显式表达合法停止条件。

检查这种区别时，使用一次性模型变体，在待保存的非终态禁用唯一的进展动作。检查器应到达该状态并报告死锁。合法静止状态仍保留受守卫限制的后继。将变体改动及实际结果保存在检查记录中。

## 检查可达性

核对初态、可达事件守卫和性质前件。模型始终不产生待保存工作时，`PendingEventuallySaved` 可以空洞成立。评价本示例时，到达待保存状态、执行提交，并展示旧确认交错。依据可以是具体路径，或获准的一次性可达性探针。

为每项性质记录自然语言含义、公式或谓词、环境条件及检查结果。提前终止可能使其他已配置性质仍未判定。结果解释见[检查](./checking.md)，完整示例运行见 [TLC](./tlc.md)。
