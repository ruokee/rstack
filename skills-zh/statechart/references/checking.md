# 选择检查

选择方法或解释覆盖时读取。让检查对象和探索方式匹配读者所需结论。选择能够提供相应证据的最低成本方法。

## 人工推演小模型

用状态说明、转移列表和小图澄清简单流程。输入为已陈述规则和初始条件。执行具体正常顺序，以及可能改变判断的边界顺序。输出为到达状态、接受或拒绝的事件及未决规则。

违反已确认规则的路径，是对这些建模规则的反例。人工探索覆盖实际跟随的路径。保存这些路径，供下一位读者重复推演。从[建模](./modeling.md)和[视图](./views.md)开始。

## 生成操作检查代码

状态式性质测试生成操作序列并执行实现。输入包括操作生成器、前件、初始化，以及独立判定依据或抽象状态。在相关操作后比较可观察结果。失败后通过缩减寻找更小的失败序列。

适合时使用项目既有框架，例如 Hypothesis 状态机或 fast-check commands。重置、身份、错误和异步完成语义采用实现契约。记录随机种子或回放数据及实际调度。生成的顺序命令列表，需要驱动程序暴露并调度相关交错，才能探索并发。

辨错依据是可观察结果与独立判定依据之间的差异。从实现照抄的判定逻辑可能重复其错误。样本量和随机探索描述实际抽样执行。

## 搜索独立模型

模型检查探索模型提供的转移系统。输入包括初态、具名动作、有限常量或取值域、环境行为及性质。结果可以是完成搜索、安全性反例、死锁、活性反例、搜索中断或工具及配置错误。

事件交错、重要不变量和进展假设适合使用模型检查。[TLC](./tlc.md) 提供本包的完整可执行路径，检查有限的显式状态模型。Quint、Apalache 等工具有各自的探索语义、边界及结果契约，选用时沿用项目已有且有据可查的设置。

完成的有限搜索支持相应模型及探索域内已配置的性质。问题涉及实现行为时，通过[实现对应](./implementation.md)将模型连接到真实代码。

## 从模型驱动实现

模型驱动测试选择合法模型动作，将其转换为真实 API 调用或受控参与者步骤。定义动作适配器、状态投影及比较时点。将观察到的实现状态和输出与模型允许结果比较。

输入包括模型、真实实现、适配器、可控调度和初始化。输出包括可回放操作序列及差异。核对适配器执行目标调用，投影保留目标性质，调度跨越真实暂停或事务边界。模型层变异检验模型的检查能力。真实代码变更或独立的错误实现检验适配器及判定依据的连接。

## 核对已有轨迹

轨迹符合性检查判断模型行为能否解释实现观察。输入包括有序事件、观察字段、关联标识和状态投影。考虑并发顺序、缺失观察、停顿步，以及由多个实现步骤表示的模型动作。

输出为注明观察缺口的匹配路径，或最早失去合法匹配的事件或状态。稀疏日志可能对应多条模型路径。记录歧义和能区分它们的缺失观察。保留来源时间戳及顺序保证，独立时钟之间的全序需要相应依据。

模型驱动执行探索选定的实现运行。轨迹符合性检查评价记录输入中已有的运行。两者都需要可信的模型到观察关系。

## 记录搜索范围

保存候选模型及配置、工具版本、命令、常量、初始条件、环境、性质、探索模式、约束、缩减、完成状态及原始输出。存在实际状态统计和完整反例时一并保留。

分别解释各项结果：

- 完成的有限搜索覆盖模型范围内已配置的性质。
- 资源中断留下部分探索。报告已探索部分及输出实际判定的性质。
- 提前失败的性质有对应反例。其他性质按检查器输出确定状态；需要更多证据时运行另行标识的配置。
- 随机模拟提供实际执行的运行及抽样调度。
- 语法错误、缺少工具及无效配置需要修复或补齐具名能力，随后才能完成依赖它们的检查。

状态约束和动作约束会裁剪探索。记录谓词，以及工具如何处理边界状态、性质求值和边界死锁。保留相关边界状态输出。在 TLC 中，越过约束的状态仍可能接受不变量求值，后续探索在此停止。覆盖判断采用具体工具版本及选项的语义。

对称缩减要求取值确实可互换，性质在互换后保持。TLC 的活性检查对对称缩减有限制；在适用工具语义提供组合依据前，使用未缩减配置检查活性。图的投影及 TLC 状态等价设置也需要各自说明。分别记录少画节点和少探索状态。

## 处理失败

采用检查器或驱动程序的实际动作顺序和状态值。定位首次安全性违反、死锁状态或反复出现的活性条件。通过[视图](./views.md)转换成读者语言。处理已有代码时，核对整条顺序是否允许，并按授权回放。

工具不可用时保留具体错误、缺少的能力、受影响性质及下一项允许动作。继续有价值的规则分析和路径推演，按实际证据类型交付。要求的工具执行保持待完成，直到能力补齐或用户批准范围变化。

完成标准：选定检查回答了请求中的判断，或已完成全部可达分析，并记录具体阻碍和后续责任人。
