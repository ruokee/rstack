# 原型

用低成本、可丢弃的原型回答具体设计问题。交付观察、取舍、建议及可运行产物，供决策者选择和正式实现接手。

工具、角色、权限及材料位置沿用宿主规则。以下步骤的投入以回答问题为准，简单问题可以只用几句话准备。

## 1. 明确决定

读取请求、已有证据及已确认约束。说明问题、候选或可行性假设、关键输入、会改变选择的观察，以及决策者。已有有效证据足以回答问题时直接使用。方向和行为均已确定时，继续已授权的实施流程。单个方案的可行性仍有疑问时，一个候选即可。

区分可观察事实和人的偏好。行为、输出及时序由相关运行取得。视觉偏好、产品优先级及可接受的取舍交给相应决策者。问题需要澄清假设时，可使用 `thinking-method`。

保持当前请求的范围。仅限比较截图时，依据这些截图交付获准的分析。回答问题确需新原型或操作时，说明所需动作，按宿主规则解决授权。

每项拟制作的内容均对应具体的待决问题，并且可以选择观察方式后，进入下一步。

## 2. 选择方向

设计空间开放时，查找相关先例，整理真正不同的方向。来源搜集需要时可使用 `research`。视觉探索可以用少量参考图或布局草图帮助用户表达偏好。沿用已确认的方向和优先级。

候选围绕实际差异选择，例如连续筛选和确认后筛选、表格和卡片、同步回调和延后回调。新增方向应帮助回答同一问题。候选数量由尚未解决的选择决定。只换名称无法形成有用比较。

剩余偏好或优先级属于用户时，请用户选择。观察可以解决的问题继续取证。

候选覆盖当前有意义的分歧，各自符合已确认约束后，进入下一步。

## 3. 制作原型

在宿主允许的任务临时目录或实验位置制作原型，与生产源码分开。依赖安装、外部写入、付费及服务操作遵循当前权限。

计入总体搭建成本，选择能真实呈现目标问题的最小环境：

- 布局或简单交互可以使用独立 HTML、CSS、JavaScript。
- 行为或时序可以使用最小可运行程序。
- 框架、组件、依赖或协议问题需要使用其实际相关机制和版本。复用当前环境可能比另建技术栈成本更低。

实现观察所需的状态和操作。生产级打包、通用抽象及长期维护设施留到正式实现。关键输入、启动方式及观察步骤应可重复。

静态数据或替代依赖可以展示布局和流程。标明每项替代、其来源及支持的判断。性能、兼容性或真实副作用的结论使用相应真实机制。

原型能触达目标行为，重要简化已有说明，产物位置和运行方法可找到后，进入下一步。

## 4. 建立比较入口

多个视觉候选共用一个切换入口，标明各自名称。保持数据、视口及起始任务可比。切换时显式保留或重置相关状态，保留正在调查的设计差异。

行为候选可以共用驱动程序、输入或命令入口，分别标记结果。时序或性能比较保持相关运行条件可比。记录数据规模、执行路径及影响结果的环境条件。

单候选可行性原型可以直接进入观察。比较工具本身保持简单。

观察者能识别当前候选、输入及状态，并重复目标操作后，进入下一步。

## 5. 实际观察

使用相应界面或运行环境，执行决定问题的操作：

- 视觉问题打开实际页面，操作相关交互，保存能够识别各候选和关键状态的截图。
- CLI 或 TUI 问题运行程序，观察真实输出及状态变化。
- 行为或时序问题执行目标路径，记录输出、事件顺序或时间。测量波动会影响判断时，进行相称的重复观察，保留波动及条件。

计数、结果比较或简短断言可以辅助取得观察。原型阶段以获得可用观察为完成依据。长期测试由正式实施流程承接。

观察工具、替代部分或比较条件使结果失真时，修正后再判断。证据仍无法区分候选时，保留实际观察和待决问题，选择最小的下一项区分性观察。环境或权限阻碍运行时，记录尝试的操作、具体原因、待完成的观察及继续条件。

结论能追溯到实际候选、输入、操作及观察，适用范围与原型真实程度一致后，进入下一步。受阻或未决的结果保留其实际状态。

## 6. 形成选择依据

交付探索过的候选、证据、取舍、建议、适用条件、产物位置及运行方式。明确说明原型是可丢弃的实验产物。决策者已确认的选择、Agent 建议及待定偏好分别记录。

证据足以支持目标决定时停止。选择仍未解决时，说明剩余问题及能够区分候选的下一项观察。每个额外变体都应有具体的判断用途。

将选定方向、需要保持的行为、关键观察及剩余条件保存到持久的任务材料。临时路径标明其保存性质，保留期限遵循宿主规则。将结果交给已授权的正式设计或实施流程。解释观察需要相应专业知识时，可使用 `code-design`、`system-architecture` 或 `ddd`。这些资料按需取用，本入口包含完整的原型方法。

正式实现按项目约束组织。是否复用某段原型代码由该实施任务判断。保留和清理遵循宿主规则，包括删除授权。

接手者能找到证据和产物，理解建议或待决选择，并按决策者已确认的偏好继续后，完成本次原型工作。

## 示例

以下为构造情景。用户希望比较记录列表的表格和卡片布局。使用同一组带长标题的记录、相同筛选条件及视口，提供标明名称的切换入口。在各候选中实际操作筛选、打开详情和返回，保存相关状态截图。

根据这些操作记录实际溢出情况及筛选后展示的记录。信息密度和留白的偏好尚未确定时，请决策者选择。结论依据实际观察填写。

原型使用静态记录时，在交接中说明其来源及支持的展示范围。真实 API 兼容性通过相关 API 路径检查。
