# 使用 rstack

你是负责理解请求、执行工作、处理结果并交付所需成果的 Agent。使用本入口选择方法。专业 Skill 提供某类活动的方法，playbook 说明活动之间的关系，包括依赖、选择、反馈和完成方式。

本入口以安装所选语言的整套 rstack Skill 为前提。保持各 Skill 目录同级，保留完整 `use-rstack` 包及其 `playbooks/` 公共流程目录。下列相对链接适用于源码目录和采用这一布局的安装副本。

## 恢复请求

读取当前请求、有效决定及工作所需的上下文。接续工作时，恢复已有安排、已完成结果、候选身份、证据、剩余范围及权限。沿用仍然有效的部分。

明确请求终点及需要用户决定的取舍。项目规则、当前目标和有效权限约束执行。读取方法本身不增加权限。

## 选择路径

核对现有方法是否仍适合当前请求及条件。保留适用的安排。需要重新选择时：

- 工作已经清楚且无需补充方法时，直接操作。
- 单个活动足以完成工作时，读取相应专业 Skill。通过下列导航选择，采用方法前先读取其完整正文。
- 工作需要衔接多项活动时，查找适用的 playbook，先读取正文再采用。

## 选择 Skill

活动按当前请求及真实依赖选择，完整的可复用顺序由具体 playbook 提供。

### 调查问题

- [research](../research/SKILL.md)：答案需要可追溯证据时，系统搜集、核验及综合来源。
- [thinking-method](../thinking-method/SKILL.md)：处理机制如何运作或为何如此、类比、开放问题、建模、第一性原理、假设及推理困难。
- [teach](../teach/SKILL.md)：帮助用户理解概念、机制或方法，包括解释后仍然存在的困惑。
- [diagnose](../diagnose/SKILL.md)：调查失败、回归、意外结果或相互矛盾的观察的原因。

### 解决设计问题

- [system-architecture](../system-architecture/SKILL.md)：确定系统边界、职责、交互、运行结构或系统级技术选择。
- [ddd](../ddd/SKILL.md)：澄清领域含义和业务规则，选择限界上下文，设计及演进领域模型。
- [code-design](../code-design/SKILL.md)：设计代码结构，或改进既有接口、模块、依赖及归属。
- [type-driven-design](../type-driven-design/SKILL.md)：设计、诊断或演进类型模型，处理数据形状、语义区别、状态及操作契约。
- [prototype](../prototype/SKILL.md)：用可丢弃实现回答设计或可行性问题，比较方案，观察实际布局、交互、行为或时序。
- [statechart](../statechart/SKILL.md)：用户显式请求时，建模状态行为、检查状态交错或维护模型。普通设计或审查可以在有用时建议采用此方法。

### 检查工程工作

- [engineering-principles](../engineering-principles/SKILL.md)：设计、实现、修改或审阅代码、文档及配置时，选择相关工程原则。
- [blast-radius](../blast-radius/SKILL.md)：从拟议或已实现的软件改动追踪受影响的消费者，选择需要复查的行为。
- [code-quality](../code-quality/SKILL.md)：判断代码、测试、代码设计、重构或迁移的质量，或选择及配置格式化、lint、自定义规则和类型检查。
- [create-verification](../create-verification/SKILL.md)：创建或维护验证方法及其支撑产物。执行已有验证方案时遵循该方案的说明。

### 面向读者写作

- [technical-writing](../technical-writing/SKILL.md)：编写、修订或审阅面向人的技术文档，例如 README、指南、参考资料及提案。
- [writing-for-agents](../writing-for-agents/SKILL.md)：编写 Agent 指令，例如 Skill、`AGENTS.md`、Prompt、Tool/MCP 描述及 subagent 任务。
- [wellsaid](../wellsaid/SKILL.md)：整理所有输出的表达，包括回复、文档、代码注释及协作消息。

### 改进已有工作

- [reflect](../reflect/SKILL.md)：检查工作会话，提取可复用经验或反复出现的流程问题。
- [improve](../improve/SKILL.md)：围绕明确目标，通过前后比较迭代既有产物。
- [create-playbook](../create-playbook/SKILL.md)：将实践整理成可复用流程、为新需求设计流程，或维护已有 playbook。

## 使用 Playbook

先读取请求明确提供的路径，再沿已加载上下文以及项目、工作区或用户既有约定中的指针查找。同时检查以下位置，已有明确替代位置时采用该位置：

- 项目或工作区流程位于相应根目录的 `.rstack/playbooks/`。
- 个人流程位于 `~/.agent/rstack/playbooks/`。
- rstack 公共流程位于相对本入口的 `./playbooks/`，源码和安装包使用相同关系。

查找范围限定在已知来源及当前需要内。私有位置独立于安装的公共包维护。

指向一份普通可读 Markdown 流程的链接即可承担入口职责。已有导航可以列出多个候选及适用条件。依据当前请求判断内容是否适用。

分别识别名称、维护来源、正文路径和适用范围。公共内容由 rstack 维护，私有内容由相应用户、项目或工作区维护。个人流程可以跨项目使用，工作区流程也可以只适用于其中一个项目。

用户指定流程时，核对所指来源及正文与请求、当前约束的关系。其他候选按适用条件和有效决定选择。公共和私有流程可以同名并存。已有替代关系时按该约定选用。其余情况保留各自来源身份，与用户解决影响结果的歧义。同名本身不构成优先关系。

默认私有目录尚未建立，或已检查目录没有适用 Markdown 流程时，使用专业方法并形成当次安排，继续工作。请求的产物包括可复用流程，或流程设计本身需要专门处理时，读取 [create-playbook](../create-playbook/SKILL.md)。保存新 playbook 需要相应的产物要求。

已声明或明确指定的来源读取失败时，保留具体错误，指出依赖该内容的选择或操作。这些部分等待来源问题解决，具备独立依据的工作继续。默认私有目录尚未建立属于正常的首次使用情况。公共 `./playbooks/` 目录随包分发，缺失时记录具体安装或来源问题。

## 采用方法

读取选定方法和相关项目约定，带入实际对象、事实、版本、权限、起点和完成条件。按指针说明的条件读取所需资料。项目命令和对象判据从权威材料取得。

按该方法及既有工作约定执行当前请求。协作角色、消息工具及验证分工沿用当前环境和有效安排。委派时提供所需上下文、输入、候选身份及结果要求。

方法选择属于工作的一部分。活动结束后继续处理已授权的剩余范围。新事实需要其他方法时重新选择。

## 协调工作

现有方法或安排需要补充时，采用以下规则。同类安排及其有效结果直接沿用。

### 安排下一活动

对安排中的缺口，明确下一活动、所需输入及预期结果。详略与工作相称。当次值及进展保存在任务已有材料中，可复用流程保留稳定的活动关系。

### 处理结果

将重要结果或新事实与目标、剩余范围对照，按需要继续、修复或更换方法。保留有效结果。改变安排时，说明依据和受影响部分，包括适用条件发生变化的证据。

### 保存暂停记录

外部依赖或跨会话需要暂停时，在现有记录中保存：

- 有效决定。
- 候选身份及对应证据。
- 剩余事项。
- 当前权限。
- 继续位置及依赖条件。

恢复时读取记录，将其条件与当前事实对照。沿用有效部分，调整受影响部分。流程发生变化时，将新指导与原候选、决定及证据分别识别。

### 判断完成

交付前，将当前请求的每项完成条件对应到结果证据。检查方式与该条件及当前权限相符。

分别判断活动完成、候选通过和请求完成。原型完成可以是仍需正式实现的请求中的阶段成果。终点为已验证候选时，交付该候选。授权范围延伸至后续工作时，继续到对应终点。Task 状态按其独立约定处理。发布、安装及其他影响较大的操作保留各自的权限要求。
