# 技术写作

组织技术材料，让读者能够完成任务、查证事实或理解决定。适用于 README、教程、操作指南、参考资料、原理说明、提案及技术报告。按请求的改动范围安排工作。

## 确定阅读任务

读取请求、现有文档及相关材料，明确读者目标和已有知识、对象的版本和状态、本次操作及获准的输出位置。区分新写、局部编辑、结构调整、翻译和审阅。

先用已有上下文解决这些问题。只询问会改变结果的缺失信息。局部编辑以受影响的阅读路径为范围。仅审阅时，交付问题及建议修改位置。

文档用途和改动边界明确后继续。面向 Agent 的执行指引使用 `writing-for-agents`。普通回复、提交信息、PR 描述及产品界面文案遵循各自惯例；请求需要形成技术文档时，使用本流程。

## 核对技术内容

从所给材料、实现、规格及已观察结果取得事实。区分实现行为、提案、解释和建议。历史原因归于支持它的记录。每项陈述保留对象、版本、状态、条件及证据范围。

核对影响读者动作或判断的细节：前置条件、名称、参数、类型、默认值、单位、输入、输出、限制、错误及副作用。来源有分歧时，检查各自的版本、配置、日期和对象。未解事实放在受影响内容旁，说明实际影响及解决问题所需的来源。

复用已有调查。具体证据缺口需要系统搜集或比较来源时，使用 `research`。机制或取舍需要分析时，使用 `thinking-method`。受影响陈述等待补齐证据期间，继续处理有依据的内容。

关键陈述有来源、已知条件得到保留、剩余缺口对文档的影响明确后继续。

## 安排内容结构

按[文档类型](#文档类型)选择组织方式。先列出读者完成任务所需的内容，再安排顺序。沿用已有的合理结构。

首次使用提供用途、前提和最短完整路径。日常查阅提供稳定分类和准确入口。评估方案提供问题、约束、备选项、依据和建议。

同一内容保留一个主要维护位置。短说明放在用到它的步骤旁，较长的独立材料通过含义明确的链接连接。读者、用途、维护来源或篇幅产生实际冲突时，再拆分文件。文件迁移及批量重组遵循当前授权。

每节服务的读者需求明确，必要背景已连接到相关步骤或陈述后继续。

## 编写文档

条件和前提放在对应动作之前。顺序操作使用有序步骤。说明谁执行、什么会改变、读者怎样辨认结果。相关失败分支靠近对应动作，提供选择下一步所需的判断依据。

使用材料中的真实标识符、命令、路径、选项及单位。同一概念使用一致术语，解释必要的别名。让指代、修饰范围、备选关系及作用范围明确。翻译保留技术含义，各语言使用自然句法。

使用能够展示行为的最小完整示例。标明占位符，在使用前解释替换值。示意片段注明省略内容。区分命令、预期输出和解释。代码格式遵循对应语言及项目惯例。正式 STE 符合性需要指定版本的完整标准和词典。

编写或修订正文前，通过宿主的 Skill 机制读取 `wellsaid`。完整指导已在上下文时直接复用。它负责通用表达及作者声音。清理文字时保留技术条件和证据限定。

请求的内容已成文，读者能够关联操作、示例及结果后继续。

## 检查交付

按读者使用顺序检查成品：

1. 从入口找到当前任务或事实。
2. 检查前提和条件是否出现在依赖它们的动作之前。
3. 将名称、命令、示例、版本、参数、限制及结果与来源核对。容易变化的统计或目录陈述按需要注明适用版本或再生成方法。
4. 检查链接、标题、代码块、列表、表格和图示在目标格式中的呈现。
5. 在授权范围内同步受影响的入口、重复说明及翻译。

具备执行授权和所需环境时，运行相关示例并观察结果。写作授权不包含文档所述操作的执行授权。检查证据区分来源核对、语法或构建检查、实际运行及读者试用。真实执行阻碍放在受影响的结果旁说明。

约定阅读任务得到覆盖、关键事实准确、适用条件和剩余阻碍清楚时完成。交付成品位置及实际检查结果，或有依据的审阅问题及建议修改位置。其他 Skill 的修改、任务管理、交付及安装遵循各自范围和权限。

## 文档类型

用 [Diátaxis](https://diataxis.fr/) 的四种需求判断内容单元的用途。它们可以指导一节或一篇文档。按当前材料需要形成结构。

### 教程

帮助学习者通过练习获得技能。先交代目标成果及学习前提，选择一条完整路径，在合适阶段给出可观察结果，必要概念就近解释。较长背景及替代路线通过链接提供。完成练习是可观察结果；掌握程度的判断需要学习者的实际表现作为依据。

### 操作指南

帮助已有相关基础的读者完成任务。围绕目标、前提、动作、结果及必要分支组织。超出当前任务的基础安装通过链接提供。失败处理应帮助读者选择下一步。

### 参考资料

帮助读者查证准确细节。按接口、配置、命令或对象的稳定结构组织，包含相关类型、默认值、范围、单位、条件及错误。事实保留版本及实现状态。示例解释字段或行为，教程和设计说明通过链接满足相应阅读需求。

### 原理说明

帮助读者理解机制或决定。围绕一个问题展开必要概念、关系及推理。交代相关背景、约束、备选项和有依据的取舍。区分已有决策记录、作者分析及当前建议。操作步骤和接口细节通过链接提供。

### 复合文档

README、RFC、设计文档和研究报告按整体用途组织。README 可以从定位进入简短使用路径，再提供参考入口。RFC 可以依次展开决策问题、约束、备选项、影响及待决定事项。研究报告可以呈现结论、证据、分歧及建议。

每节用途明确，阅读路径连续。复用已有专门页面。小文档可以通过清楚分节保留多种阅读需求。
