# 软件迁移

按[系统演进](../core/evolution.md)明确保留义务及变化原因。本参考定义代码、消费者、状态及权威怎样过渡。关键阶段需要负责人、进入条件、完成证据及恢复条件。

## 选择变化边界

消费者可同步改变，且可接受的暂停能处理在途工作时，完整切换可能更简单。绞杀者将明确能力或流量分组路由到替代实现。路由边界需要覆盖全部相关入口，并保留操作标识及状态权威。

抽象分支把可替换实现放到内部契约后，再迁移调用方，可以支持广泛依赖的渐进替换。临时接口及开关增加维护，也可能隐藏能力差异。切换义务结束后删除过时路径。

Expand-contract 先引入共存期可用的表示，再迁移消费者及存量状态，最后删除旧表示。明确共存的读写版本及各自对每种表示的处理。消费者可能包括后台任务、旧客户端、历史事件及恢复工具。无需兼容时采用直接切换。

## 明确各范围的权威

每阶段为每个实体、分组或能力定义权威写入者。读取路由及写入权威分别决定。说明切换时的在途请求、定时任务、排队事件及缓存路由。通过排空、写入隔离、epoch 或等效机制阻止旧写入者提交，才能维持权威切换。

独立双写可能部分成功。先旧后新可能让新库落后，先新后旧可能让旧库落后。两边重试需要标识及重复安全性。明确哪个已提交事实决定修复，以及已确认操作怎样跨重启保留。源事务加 Outbox 或可恢复日志可以让复制跟随单一权威。两次分别成功的调用本身会留下原子性缺口。机制见[一致性](./consistency.md)。

## 保留并发变化

构造同一实体的时序：

1. 回填从旧库读取并保留 `order-A` 的版本 1，状态为 `pending`。
2. 实时更新在源提交版本 2，状态为 `completed`。
3. 复制将版本 2 应用到新库。
4. 回填尝试写入保存的版本 1。

最后一步无条件写入会恢复旧状态。需要协调快照及实时变更流，或让目标端安全处理旧版本。机制覆盖实际顺序及事务契约。

一种方法是取得与源日志位置 L0 对应的一致快照，保留从该位置开始的变化，加载快照后按源顺序应用变化。定义快照及日志交接，覆盖全部已提交变化，日志保留到全部必要消费者通过该位置。按分区等顺序范围分别跟踪源位置及应用位置。源头持续前进时，需要有界比较或切换屏障。

快照加载与变更应用重叠时，目标可以通过原子比较及写入，只应用更新的源实体版本。相同版本应表示同一逻辑效果，或有明确冲突规则。版本需要源定义的实体内顺序，以及删除和重建规则。按本地到达时间排序会让迟到旧数据覆盖新值。

通过墓碑或等效有序变化捕获删除。墓碑保留到迟到快照及重放可能重新引入该实体的期限结束。重建标识需要 generation 或排序规则来区分。重放事件需要重复安全性。多行不变量需要按事务应用，或明确接受中间可见状态的契约。

持久化回填进度及修复状态。完成标准覆盖失败批次、转换、源日志缺口及目标错误。向量索引回填还消耗嵌入容量及费用，需要记录文档及嵌入版本。

## 定义切换阶段

基于源日志的迁移可以按实际契约采用以下阶段：

- 准备：旧库拥有写入及读取。建立兼容消费者、快照及日志位置、变更保存及目标应用契约。旧服务继续有效时，恢复可以放弃尚未使用的目标工作。
- 填充：旧库继续权威写入。回填并捕获实时变化，跟踪水位、删除、失败及语义不变量。源及保留日志仍覆盖必要历史时可以暂停填充，历史丢失后需要重新取得一致数据。
- 比较：旧库继续拥有写入。比较对应版本或计入复制延迟。数量检查会遗漏错值及缺少的删除，需要核对关键查询、标识、金额、访问行为及不变量。新鲜度契约允许时可单独切换读取。读取返回旧库需要旧库满足读契约。
- 转移权威：建立屏障，排空或隔离旧写入者，完成至屏障位置的变化，确认目标就绪，再把后续操作交给新权威。说明被拒绝、排队及在途操作怎样继续。短暂停顿不可接受时，采用具有同样明确顺序及隔离的分范围所有权转移协议。
- 退役：恢复义务及剩余消费者已经处理后，结束复制，删除旧写入路径、开关、任务及表示。按实际保存契约保留必要历史及恢复材料。

差异率验收目标需要定义允许的差异。很低的平均差异率也可能掩盖不可接受的金额或删除错误。切换条件依据不变量及运行目标。

## 隔离影子执行

影子工作在服务实现的结果继续权威的同时，与候选进行比较。阻止候选发出真实支付、通知、共享业务状态写入或其他外部效果。通过效果边界记录拟执行动作，或使用隔离目标。为影子工作限定资源预算、分开观测，避免耗尽生产容量或计入真实业务完成。

在隔离边界记录候选失败，定义比较怎样处理它。服务操作继续遵守自身错误契约。确定值按要求精确比较，开放 AI 回答按 [AI 评估](./ai/evaluation.md)比较。使用生产流量需要当前任务授权。

## 转移后恢复

新方独有写入会让直接返回旧库留下缺口。例如新库已经有 `order-A=completed` 及新建的 `order-B`，旧库只有 `order-A=pending`。只反转路由会丢失当前状态及已接受义务。

按契约选择恢复机制，包括从新权威有序反向复制、可重放的提交历史、暂停后同步并转移回权威，或继续由新方掌权并向前修复。反向同步需要冲突及循环处理。转回权威前，确认旧格式能表示新事实、旧代码能解释它们，并再次隔离退出方写入者。

已付款、已发消息及其他不可逆效果需要有效补偿或核对。明确谁处理未知结果及剩余工作。回退开关控制路由，当前数据、兼容行为、有效权威及已交代的效果建立恢复路径。
