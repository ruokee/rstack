# 数据权威

对每类事实定义权威、允许的写入者、访问形态、生命周期、派生副本、可容忍陈旧程度及恢复方式。权威取决于数据契约。对象存储或专用数据库也可以像关系库一样拥有自身数据。

## 定位状态

无状态计算在操作之间不保留必要进度，通常更易复制，同时仍会消耗 CPU、内存、连接及下游容量。有状态工作需要归属、持久化及实例接管时的协调。把状态移到共享存储会将这些义务集中到该存储。

区分业务事实、执行进度、缓存结果、搜索索引及分析投影。说明不一致时以谁为准，谁修复派生副本。不同字段、实体或操作可以具有不同权威，需要明确作用域。

构造情景：对象存储拥有上传文档的字节，元数据数据库拥有文档访问权限及版本标识，搜索索引派生可检索内容。重建索引需要源版本及权限元数据。单独更新索引会保留源文档原有的权威归属。

## 保护不变量

列出可能违反规则的操作，包括并发写入及陈旧读取。余额非负可能需要条件更新，以及关联账务记录的事务。对账可以在提交后发现错误，它承担恢复作用，预防违反需要提交时的机制。

ACID 描述事务原子性、维持约束的一致性、隔离性及持久性。数据库实际保证取决于配置及操作。BASE 描述偏向可用性及最终状态的设计取向。CAP 关注分区期间的分布式运行。它们回答不同问题，系统可以组合本地事务及异步投影。按[一致性](./consistency.md)明确所需观察及事务范围。

## 判断副本

- 复制把同一数据集放在多个节点，可以增加容错及读取能力。同步及异步复制在提交延迟、失效行为及可能丢失的数据上不同。读副本可能返回旧数据。增加副本仍需处理单写入者的协调及提交容量。
- 分片按路由规则划分数据责任，负载能分散到不同键时，可以分摊存储及写入。跨分片查询及事务增加协调，热键或倾斜可能主导容量。选择依据实体局部性、查询形态、增长及重分片成本。
- 缓存提供保留的结果或副本，减少重复工作，同时增加新鲜度及失效义务。明确源权威、键的作用域、版本、有效期、刷新及丢失后的行为。权限或价格等缓存决定需要可接受陈旧程度的契约。

缓存失效存在并发竞争。读者先加载旧值，写者更新源并删除缓存，随后读者又把旧值填回缓存。TTL 只有在给定刷新及返回规则下才限制该副本的寿命。版本、同步失效或读源可以以相应代价建立其他契约。

空值缓存可以减少重复查空，需要处理新数据创建后的过期规则。Single-flight 可以合并同键的并发重建。过期时间抖动可以分散刷新负载。共享缓存失效后仍需要源容量或受控准入。详见[容量](./scaling.md)。

## 跟踪生命周期

定义产生、校验、改变、保存、归档、删除及恢复。要求覆盖备份、日志、投影及导出副本时，将它们一并纳入。恢复备份可能重新引入已删除记录，需要恢复流程重放相关删除历史。

改变实体标识、关系、格式或路由，可能需要对真实存量数据进行转换及兼容。按[软件迁移](./migration.md)围绕实际消费者及在途工作规划。具体操作及约束下的存储选择见[存储](./selection/storage.md)。
