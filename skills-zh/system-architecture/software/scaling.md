# 容量

先在实际负载下定位受约束资源，再选择容量改动。分开平均吞吐、突发、并发及延迟分布。一般流量及稳定窗口判断见[系统动态](../core/dynamics.md)。

## 衡量资源需求

按操作类别归因 CPU 时间、保留内存、连接、存储 I/O、网络、持久存储及并发。计入扇出、后台任务、重试、缓存重建、复制及迁移。集群低平均值可能隐藏单个工作者、锁、分片或键的饱和。

构造估算：每秒完成 200 次操作，每次平均 0.5 秒内保留 2 MB，则活跃操作约保留 `200 × 0.5 × 2 = 200 MB`。这是稳定窗口估算，范围之外还包括空闲进程、缓存、边界外队列及大小变化。峰值及尾部要求需要各自观察。

M/M/1 模型假设 Poisson 到达、独立指数服务时间、单服务者，且到达率 λ 小于服务率 μ。平均系统停留时间为 `1 / (μ - λ)`，包括服务时间；平均排队时间为 `λ / (μ × (μ - λ))`。接近饱和时的延迟增长解释了该模型的行为。真实负载需要实际波动及排程前提。预留容量依据所需结果，避免套用统一 CPU 比例。

## 选择资源变化

垂直扩容可以增加 CPU、内存或 I/O，协调变化较少，也有价格及物理限制。原有冗余可以继续保留。水平复制增加运行实例，收益受共享状态、下游配额、协调及路由限制。新增节点提供容错还需要正确接管。

围绕已定位资源比较减少重复工作、索引、批处理、缓存、single-flight、准入变化、复制及分片。批处理分摊准备开销，代价是等待及更大的部分工作。无状态副本仍会共享依赖。写瓶颈可能来自多余写入或锁竞争，也可能来自存储容量。

## 分配状态

范围分区保留范围操作局部性，也可能集中当前时间流量。哈希分区在哈希前提下分散不同键，同时让范围查询跨分片。单个热键仍然集中。读副本或本地缓存可以分摊读取，将计数器拆成多键可以分摊写入，同时增加聚合及一致性工作。

在均匀哈希及节点编号稳定的模型下，`hash(key) % N` 改成 `% (N + 1)` 会移动约 `N / (N + 1)` 的键。平衡的一致性哈希环向 N 个节点加入同容量节点时，预期移动约 `1 / (N + 1)`。虚拟节点可以减轻随机不均。位置均衡仍需另外处理请求频率差异及热键。重分片会在正常工作继续时消耗存储、网络及写入容量。

Single-flight 在协调范围内合并同结果的并发请求，需要限制保留的等待者，定义失败及取消行为。抖动分散不同键的刷新。刷新期间返回旧值需要明确年龄上限及业务许可。多级缓存每级都增加失效及冷重建行为。

## 计算尾部影响

n 个独立同分布的并行调用全部完成时，单调用延迟分布函数为 F，则最大延迟的分布函数为 `F(t)^n`。单调用以 0.99 概率满足门槛时，100 个全部满足的概率为 `0.99^100 ≈ 0.366`。共享依赖及相关延迟会破坏独立性。完成规则改变后需要另算。

延迟对冲在等待达到门槛后发起第二个合适请求，使用首个有效结果。在稳定连续分布、无提前错误且门槛为 p95 时，约 5% 的操作会多发一次请求。这衡量请求数，CPU 或连接成本需要另算。两个副本在途时都占用资源，取消可能延迟，共同慢因也会限制收益。采用重复安全操作及负载预算。

按所需延迟及失效条件测量容量收益。协调开销会让额外并发收益递减甚至为负，Universal Scalability Law 描述了这种模型。外推前用相关观察拟合。明确什么负载或资源变化会触发重新决定。过载处理见[韧性](./resilience.md)。
