# AI 基础设施

为已定位的知识、行为、质量、延迟、数据位置或成本问题选择基础设施。按[架构决定](../../core/decisions.md)保留可行现状并比较生命周期义务。

## 定位限制

沿任务追踪上下文准备、检索、推理、工具及结果处理，测量限制所需结果的阶段及负载分布。模型容量增加会留下来源材料缺失问题。更快索引会留下工具效果错误问题。

## 选择模型托管

托管 API 提供模型服务契约，模型、配额、价格、版本变化、数据处理及可用性取决于提供方。应用负责集成、使用、质量及自己承诺的恢复行为。

自建推理提供对兼容模型产物、放置、服务软件及容量的控制，同时接下加速器内存、吞吐、批处理、缓存、扩缩、升级、故障及支持责任。模型许可、硬件、数值格式、上下文行为及服务版本约束可运行对象。

混合方式可以把不同任务或数据类别放到不同宿主。路由增加质量决定及运行依赖，需要评价路由选择、任务交接及各项承诺的恢复行为。共享集成值得时，网关可以集中已采用策略及用量核算，同时增加自身可用性和归属要求。

按实际假设计算比较。实际发生时，计入输入、缓存输入、输出、嵌入、重排、工具调用、重复尝试及评价器调用。有效任务成本等于相关总成本除以满足所定义成功标准的任务数量。自建还需按所选生命周期计入采购或租赁、空闲容量、冗余、工程、适用时的电力、升级及事故。按所需质量及延迟比较。

## 选择上下文获取

长上下文把选定材料直接提供给模型，需要评价有效容量、关键事实注意程度、延迟、价格、来源标识及更新。材料装得下之后，还需评价回答质量。

检索为当前查询选择证据。按实际需要设计内容获取、版本、切块、词项或向量搜索、过滤、重排及引用标识。分别衡量检索相关性及有依据的回答质量。现有关系库搜索或进程内索引都可以成为可行方案。专用向量存储需要在召回、过滤、更新行为、延迟、规模或运维上取得可测收益。只有文档数量会留下比较问题。

缓存可以保留嵌入、检索内容、模型前缀或最终回答，需要定义键作用域、新鲜度、共享权限、失效及模型或来源变化的影响。前缀缓存可以在保留逻辑输入内容的同时减少重复处理。最终回答缓存复用先前结果，需要自己的正确性契约。

## 选择模型适配

提示及上下文变化可以在训练之外改善任务行为。微调使用合适训练样本更新模型参数，以满足目标。比较它与提示、检索及模型选择的质量和生命周期成本。检索可以提供当前证据，微调可以适配行为。参数更新对知识准确、新鲜及引用需要各自取得证据。

训练基础设施负责具有许可及版本的数据、任务、加速器及互联、检查点、产物、实验记录、评价及晋级。托管微调可以按契约承担部分义务。自管训练需要实际控制要求及持续维护能力。训练及推理具有不同资源和恢复模式。

## 选择执行支持

按应用所需状态、工具契约、并发、取消、检查点、恢复及观察能力比较框架。确认保存状态怎样对应外部效果。所需权限、批准、资源限额及停止结果按 [AI 系统](./systems.md)确定。

通过[评估](./evaluation.md)在代表任务上核对候选变化。记录运维负责人、采用工作、持久产物及退出路径。产品能力及价格按所选模型、版本、服务档位及当前一手资料核对。
