# AI 系统

围绕真实任务及后果设计。模型依据所给上下文生成或选择输出。周围系统确定哪些事实具有权威、哪些动作实际生效，以及工作怎样完成或恢复。

## 分配责任

- 模型产生回答、分类、计划或建议动作。输出可能随输入、上下文、采样及模型版本变化。
- 上下文组装为当前调用选择指令及证据。按实际信任模型保留来源标识、相关版本，以及权威指令和所给内容的区别。
- 检索寻找候选证据，负责索引、新鲜度、选择及来源引用。回答仍需要正确使用检索材料。
- 工具暴露操作，明确输入、输出、错误及效果。执行边界落实已采用权限及业务不变量。
- 执行状态记录待执行步骤、尝试、操作标识、检查点及恢复责任。业务系统拥有对应的持久事实及已提交效果。
- 长期记忆为后续任务保留选定信息，需要定义权威、来源、纠正、过期及访问契约。已存摘要可能遗漏恢复操作所需事实。
- 协调者选择后续步骤、分派工作、汇总结果，并识别完成或停止条件。赋予它承担角色所需的状态及权威。

这些是逻辑责任。单个进程可以承担多个角色，前提是契约清楚。

## 选择决定范围

重要转移可以预先规定时，采用固定工作流，单步仍可以使用模型。任务需要根据执行中的发现作决定时，动态规划可以获得相应收益。按需要组合固定业务转移及动态调查、推理。

比较实际完成质量、延迟、成本及恢复工作。多个 Agent 可以分开独立工作或专业能力，同时增加协调、冲突建议、共享状态竞争及扇出。协调者需要决定结果怎样改变权威任务状态。

## 分开建议及效果

执行服务可以机械建立允许操作、精确金额、状态转移前提及重复处理等要求。把已采用不变量放在效果发生处。提示传达意图，产生效果的代码需要对应机制。人工批准、花费限额及停止条件来自系统实际策略或显式设计决定。

构造情景：助手检索退款政策并建议退款。回答评价检查是否引用正确政策、覆盖相关条件及取得有依据的结论。退款操作另外需要获授权账号、精确金额、有效状态及稳定业务操作标识。流畅回答及成功工具传输之外，还需要判断业务是否完成。

提供方可能已退款后超时时，保留未知状态，明确负责人执行查询或核对。按提供方重复及查询契约恢复同一操作。[一致性](../consistency.md)解释外部效果边界。重复工作前，恢复需要核对已提交效果。

## 设计执行期限

跟踪模型调用、上下文大小、工具使用、并发工作、经过时间及实际价格。更多步骤还可能增加上下文及扇出，总成本按实际调用计算。模型路由、批处理、缓存或上下文压缩需要证据表明它们保留所需质量。

区分调用方取消及停止正在执行的工作。记录哪些工作仍可能完成，以及调用方怎样取得结果。检查点需要足以恢复或核对待定效果的持久状态。协调者重启后需要区分建议动作、已提交动作、未知结果及确认结果。

资源及停止策略需要执行者、可观察状态及耗尽后的明确结果。按任务选择失败处理，例如返回部分回答、保留待定工作或转移责任。预算及过载见[韧性](../resilience.md)。

## 评估完整路径

按任务检查实际模型版本、提示、检索材料、工具、状态及效果。把错误归因到负责机制及后果。内容作者身份本身会留下正确性问题。质量比较见[评估](./evaluation.md)，托管及上下文方案见[基础设施](./infrastructure.md)。任务信任或权限要求影响结构时，读取[安全](../security.md)。
