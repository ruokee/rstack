# 一致性

从不变量及可能违反它的操作开始，例如唯一分配、账务金额守恒或一次业务操作只退款一次。明确每项保证覆盖的对象、事务、观察者及外部效果。

## 明确观察契约

一致性模型描述不同契约。说清需要哪一种及其范围。

- 线性一致使每次操作看起来在调用至响应之间的某一点原子生效，顺序遵守实时先后。一个操作在另一个操作开始前已经完成，前者就在后者之前。对象可以是键、集合或服务定义的其他范围。并发操作可以采取任一符合契约的顺序。副本可能通过等待或拒绝读取来维持契约。
- 可串行化使已提交事务等价于某个串行执行，顺序可以与实际时间先后不同。严格可串行化还遵守事务间的实时先后。
- 顺序一致在共同顺序中保留每个参与者自身的操作顺序。跨参与者的实时先后是另一项要求。
- 读己之写保证会话后续读取反映本会话的写入。单调读保证会话观察的版本不倒退。单独一项会话保证不足以建立全局顺序。
- 因果一致保留因果依赖，例如看到回复时也能看到原消息。并发独立更新需要冲突规则。
- 最终收敛承诺更新停止后，在系统假设成立、通信及协调完成时副本收敛。有界陈旧期限需要额外契约。

核对数据库的实际隔离级别及访问路径。弱隔离事务可能出现写偏差或丢失更新。单键线性一致把跨键不变量留给多对象机制。“强一致”这个词省略了这些范围。

## 提交本地变化

业务状态、去重记录及 Outbox 行都在同一事务资源内时，本地事务可以原子提交它们。还需要隔离、唯一约束、条件写入或锁来保护并发请求下的不变量。

构造情景：同一进程的两个模块都能预留库存。一个事务读取可用库存，按条件扣减并创建预留记录。全部获准写入经过同一个保护不变量的操作，或由共享存储强制约束。拆成服务会增加通信及部分失败。进程数量与权威划分分别判断。

两阶段提交协调参与事务资源的原子决定。参与者持久化准备状态，再遵循协调者持久化的提交或中止决定。决定不可取得时，已准备的参与者可能持锁阻塞。恢复依赖持久化记录及解决未决事务的方式。将代价与不变量的实际需要比较。普通第三方 API 只有明确参与该协议时才进入此契约。

## 协调已提交步骤

Saga 通过本地提交及业务上有效的补偿推进。说明步骤之间什么状态可见、哪些操作仍能继续、谁安排恢复，以及补偿失败怎样处理。补偿向既有历史增加新的业务动作。数据库回滚在自身契约内撤销尚未提交的工作。

已结算付款可以用退款补偿其金额效果。已发消息可以通过更正处理。原外部动作仍然属于历史。库存补偿还需要处理货物已经消耗或另行分配的情况。

编排者负责推进，提供集中查看卡住操作的位置，也带来协调状态及可用性管理。编舞由各参与者响应事件，推进及恢复责任分布在参与者之间。按可见性、变化耦合及恢复需要选择，步骤数量本身不足以决定。

## 投递已提交事实

Outbox 在同一本地事务内记录业务状态及事件。投递器轮询已提交行，或跟踪事务日志后发布。发布后、记录成功前崩溃会造成重复投递。消费端需要重复安全的效果及保留重放记录的策略。持久积压还需要责任人及恢复能力。

变更数据捕获 CDC 从日志或等效来源读取已提交变化。明确快照位置、日志保存期、结构变化处理、重启位置及顺序范围。顺序可能只在某个源日志、分区或实体内成立。重新分区、并行投递及目标端应用会改变消费者的观察。数据库提交顺序本身省略了下游的顺序保证。

在各自投递及恢复前提成立时，Outbox 和 CDC 可以弥合事实提交与最终发布之间的缺口。代价是投递状态、延迟及运维工作。消费者事务及外部效果仍由其自身机制承担。

## 建立重复安全性

本地操作要实现重复安全，需要定义：

- 稳定的业务操作标识，作用域包含相关调用方或租户及操作类型。重试复用它。含义改变的新请求需要新操作，或明确返回冲突。
- 持久化唯一约束或串行机制，处理相同标识的并发请求。
- 在受控资源内原子提交业务效果及完成记录，并保存需要重放的结果。
- 首次执行仍在进行时，以及完成或失败后的行为。
- 覆盖允许重试及延迟投递的保存期。过期后由额外的业务唯一约束或明确的到期策略决定重复是否有效。

在非原子效果之前记录键可能永久跳过操作。在效果之后记录键可能在崩溃后重复效果。唯一约束只协调其控制资源内的并发键。结果重放按 API 契约保留原业务结果。

## 处理外部未知结果

构造退款情景：第三方已完成退款，响应随后丢失。调用方超时，本地请求表仍为 `pending`。本地数据库控制这条记录。第三方控制退款效果。

核对第三方是否接受同一稳定操作键、键的作用域及保存期、并发重复怎样处理，以及怎样查询结果。持久化操作键，显式进入未知或待核对状态。指定组件查询状态、消费可靠的完成通知或核对记录。未决操作需要升级处理的负责人及明确的下一步。

第三方去重覆盖重试期限及并发时，在该契约内复用相同键，并持久化确认结果。满足这些条件的合理方案可以得到零问题结果。第三方缺少重复安全执行时，再次产生效果前先确定原结果。盲目换新键会产生另一次退款机会。受限重试还需要满足[韧性](./resilience.md)中的条件。

传输层的恰好一次声明也需要相同的边界分析。消息系统的消费、处理及生产事务可以覆盖自身记录。事务之外的支付或邮件需要自身契约。至少一次投递加本地去重，只有在上述原子性、并发、标识及保存期条件成立时才得到一次本地提交效果。

## 选择历史存储

事件溯源保存权威领域事件，并通过重放得到状态。事件含义、完整性、顺序及演进保持有效时，它支持历史重建及新投影。代价是事件版本处理、重放开销、快照管理及保存义务。重放时分开处理状态重建及重复外部效果。

CQRS 分开写模型及读模型，可以采用同库或异库，也可以采用或省略事件溯源。独立投影可以优化查询、隔离读取负载，同时带来新鲜度、修复及重建契约。同一事务内同步更新和异步投影提供不同保证。查询或运行收益足以支付额外模型及同步工作时再选择这种分离。
