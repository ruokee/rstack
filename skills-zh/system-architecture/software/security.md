# 安全边界

按系统实际安全要求、资产、访问路径及威胁假设评估。已有网络及组织控制是模型中的事实。新增机制针对已明确的要求或风险缺口，并说明运行负责人及代价。

## 追踪访问

确认谁能行动、持有什么权限、涉及什么操作及资源，以及在哪里检查权限。认证建立身份，授权决定该身份能否对具体对象执行动作。网络位置可以属于现有访问策略，保留该策略的实际范围。

沿相关信任边界追踪数据。STRIDE 提供假冒、篡改、抵赖、泄露、拒绝服务及提权问题，选择威胁模型中相关的部分。区分预防、发现及恢复，按日志或告警的实际作用判断。

评估边界失效后的后果。分层控制保护不同失败路径时，可以限制事故影响。零信任方法把更多访问决定放在身份及请求上下文，也会增加策略、可用性、延迟及运维依赖。控制按当前威胁模型选择。

## 匹配隔离义务

池化资源共享容量及成本。独立 schema、存储、账号、进程或物理资源提供不同隔离。明确所需属性，包括数据访问、资源干扰、管理权限或故障控制。

构造租户情景：查询含租户过滤，缓存键却只有 `user:123`。缓存命中可能绕过查询过滤，返回另一租户的结果。按实际契约沿查询键、存储路径、后台任务、导出及管理追踪租户身份。共享访问层要覆盖真实绕过路径，才能建立隔离。

资源池隔离可以限制过载，数据授权需要另外的机制。独立凭证可以限制访问，共享服务的可用性依赖仍然存在。说明受保护属性及剩余共同原因。

## 交代凭证

按现有策略确定各组件需要什么凭证、怎样取得、哪里存在副本，以及怎样撤销或替换。部署、日志、备份、调试及恢复属于风险范围时一并纳入。按暴露范围、故障期间访问可用性、可审计性及维护比较保管选择。

发现实际凭证暴露时，遵循相关事故流程及权限。删除一份可见副本后，已授予权限及其他副本仍需按该流程处理。

## 纳入依赖

按相关要求沿源码、包、构建工具、产物及部署权限追踪供应链。版本锁定提高可重复性，清单说明用了什么，扫描发现覆盖范围内的已知问题。可复现构建在给定输入下比较产物，可复现的恶意源码仍然有害。每项机制按实际保证判断。

将适用的数据驻留、保存、删除及审计义务转成数据位置、访问、传播及恢复要求。专门法律解释由相应权威承担。

AI 系统中的外部检索文本可能影响工具动作提议。执行层在效果边界落实系统实际权限及业务契约。提示词提供指导，访问检查及动作执行需要各自机制。状态及工具责任见 [AI 系统](./ai/systems.md)。
