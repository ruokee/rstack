# 运行时

分别选择语言、运行时及框架，再评估组合。按[架构决定](../../core/decisions.md)处理真实交付及运行问题，并纳入当前技术栈。

## 识别约束

语言影响表达、类型、工具及可用库。运行时影响执行、并发、内存、启动、打包及互操作。框架提供路由、持久化、配置及集成的约定和生命周期。项目采用的默认值才成为该项目的要求。

说明关键操作及未达目标。换栈前归因 CPU、内存、启动、I/O 等待、协调及交付困难。慢查询换语言后仍然需要解决存储问题。核对所需库、部署目标、支持期限、调试、分析工具及能维护结果的人。

## 比较执行模型

托管运行时可以提供自动内存管理及成熟应用工具。按实际配置衡量预热、垃圾回收、内存及启动。JVM 语言、Go 及 JavaScript 运行时在这个大类别下仍有不同机制，类别标签省略了实际成本。

回调及时让出执行时，事件循环可以高效处理并发等待。循环内的 CPU 密集或阻塞工作会延迟其他请求。工作线程、独立进程、原生库或另一个运行时可以转移工作，同时增加通信及生命周期成本。Python 生态可以让原生库承担计算或推理，Python 负责协调。其并发保证取决于解释器、构建、版本及库。

提前编译的原生代码可以提供直接资源控制。Rust 所有权模型在语言及安全边界内提供编译期保证。采用仍需要可用库、领域建模、调试能力及学习时间。内存安全之外，业务不变量及分布式效果仍需自身机制。

## 判断框架约定

比较框架已提供的能力及团队原本需要维护的内容。强约定可以减少做法分歧及上手成本。较小框架可以用更少的强制依赖提供所需控制。两种选择都需要升级路径，以及观察和检查实际生命周期行为的方式。

多语言增加构建、发布、监控、调试、招聘及审查工作。具体负载或必要生态可以证明不同运行时值得这个成本。责任确实跨越边界时，保留稳定契约。

构造情景：入口路径存在已归因的运行时资源限制，有明确延迟目标，人员也具备替代运行时的运维能力。只迁移入口可以取得独立容量，并保留原业务状态权威，代价是另一条交付路径及网络契约。实际延迟来自业务权威数据库时，换运行时会留下该限制。

记录选择范围、测量或假设的收益、采用成本及重审条件。消费者或持久状态需要过渡时，读取[软件迁移](../migration.md)。
