# 系统视图

按读者问题选择视图。图应该揭示用文字较难追踪的关系或运行后果。简单安排可以只用简短文字说明。

## 选择问题

- 上下文：系统内有什么，谁使用它，哪些外部参与者限制它？
- 结构：哪些参与者承担责任，它们怎样联系？
- 流转：工作、信息、物资或资金流向哪里，在哪里等待？
- 时序：谁先行动，等待什么，结果缺失或迟到后怎样处理？
- 状态：什么改变对象状态，允许哪些转移，谁能触发？
- 物理安排：哪些资源共用场地、基础设施、访问通道或故障域？

每张图保持清楚的观察尺度。问题涉及逻辑责任及物理位置的关系时，分别表示它们。复杂对象可以用多张聚焦视图解释，同一责任在各图中的名称及含义保持一致。

## 说明关系

为关键联系标明含义及方向，例如接收工单、拥有记录、请求批准、供应备件或依赖供电。区分信息传递及责任转移。画出当前有意义的边界，包括系统范围、组织权威或资源隔离。

构造维修情景：流转图显示受理把已接受工单交给排程，缺件等待在备件齐全后返回排程，维修把完工对象交给验收，返工返回维修。责任说明写明缺件期间的负责人。该负责人在流转中保持一致。

失效或迁移决定选择时，画出相关分支或阶段。单独的成功时序会隐藏未知结果或未完成交接的责任。

## 保持可读

提供理解图所需的目的、范围及假设。细节以影响判断为准。一张图混合不相容尺度，或迫使读者拼接多条无关路径时，拆成多图。

将图与事实或拟定契约核对。重要箭头对应真实交互或明确的预期交互。图提供描述，运行机制提供保证。C4 软件抽象及部署实例见[系统结构](../software/structure.md)。
