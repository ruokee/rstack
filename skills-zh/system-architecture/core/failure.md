# 系统失效

沿具体能力损失追踪系统承诺怎样变化。失效可能是设备退出、人员缺席、供应中断、交接遗漏、信息过期、资源耗尽或恢复失败。

## 追踪传播

说明起始事件、暴露方式、依赖它的工作、剩余能力及未能履行的义务。区分失效部分及全部受影响范围。共享基础设施、供应商、批准权或工作记录会让看似独立的替代方案同时失效。

构造维修情景：两个维修台共用一台校准设备。该设备退出后，两个维修台都无法交付已验证工作。新增维修台保留了这个共同依赖。替代校准途径只有具备所需能力、容量、可用性及验收权时才构成有效备用。

完整停机之外，还要考虑延迟及错误结果。过期备件信息可能安排出无法开工的工作。缺少交接确认可能让双方都以为对方负责。实际起因的诊断按任务范围展开，架构评估可以单独识别传播机制。

## 比较应对

隔离限制受影响工作或资源，代价是独立容量及协调。备用能力需要独立于起始原因，并能及时接管。延期需要等待位置、承诺及负责人。缩小服务范围需要明确可接受的结果。人工接管需要权限、信息、受训人员，以及足以承担预期持续时间的能力。继续操作会产生不可接受损害时，停止可以保护不可逆义务。

按保留的结果及接受的代价选择应对。备用人员或设备已经满负荷时，名义备用可能缺少接管能力。全部转移过去可能再次造成过载。

## 按实际状态恢复

重复执行前，确认已经完成的工作及不可逆效果。结果未知时安排核对。首次响应缺失后再次派送、采购或维修，仍可能产生实际代价。

说明谁接管、当前权威记录、所需资源、接管条件及恢复服务的证据。覆盖未完成工作、重复分配及积压。恢复初期可能比常态运行消耗更多容量。

从实际义务定义可接受的记录损失及恢复时间。备用设备解决设备失效，可恢复记录及能使用记录的人解决工作连续性。恢复证据匹配失效情景，相关时覆盖共同依赖。

缺件时工单继续明确归属并保持可见。负责人确认新供应安排、更新承诺，把齐备工作重新交给排程。所需结果及剩余义务都已交代清楚时，恢复才算完成。
