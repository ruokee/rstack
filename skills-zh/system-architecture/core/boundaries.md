# 系统边界

围绕预期结果及可用控制能力划定系统边界。外部参与者的承诺、资源或决定会限制结果时，将其纳入说明。边界表达谁对谁承担什么义务。

## 分配责任

区分服务提供者、决定者、信息权威、资源持有者及完成负责人。同一参与者可以承担多种角色。分开说明可以暴露权力缺口及义务冲突。

每项重要交接明确输入及标识、接受条件、承诺结果、完成证据、进度可见性及异常责任。说清责任何时转移。发送方发出和接收方接受是不同事件。接受得到确认前，需要有人承担未决交接。

构造维修情景：受理岗位承担客户承诺及工单记录。备件协调者确认库存及预计到货。排程者把可开工任务分给维修岗位。验收确认维修结果后工单关闭。缺件期间明确谁跟踪工单、通知客户及重新交给排程。给供应商发送请求后，客户义务仍属于维修服务，除非约定契约明确转移。

## 区分边界类型

- 领域边界保留一致的含义及规则。“完成”的不同含义可能需要转换。
- 组织边界分配人员、决定权及责任。
- 运行边界定义独立运行或故障隔离的工作及资源。
- 代码边界控制表示、依赖及允许的访问。

这些边界可以重合，也可以分别安排。一个软件模块可以在同一进程内拥有领域规则。多个服务仍可能需要同步发布。说清需要哪种独立性，包括权威、发布、扩容、故障隔离或替换。

## 选择协调方式

集中协调可以让优先级、共享资源分配及恢复更清楚，也会形成决定瓶颈及协调者依赖。参与者具备足够本地信息及权限时，分散决定可以减少集中等待，同时增加协商、冲突处理及承诺不一致的风险。

共享能力可以减少重复工作、集中稀缺技能，消费者同时依赖其容量、优先级、契约稳定性及恢复。外部采购可能更快提供能力，也带来采购、服务承诺、数据或物资转移及退出义务。按[架构决定](./decisions.md)比较真实自有能力、差异化价值、完整成本及替换条件。
