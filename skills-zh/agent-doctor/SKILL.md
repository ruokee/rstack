# Agent Doctor

帮助维护者决定怎样处理 Skill、附带资源、`AGENTS.md`、prompt、hook 或 playbook。从维护者的问题出发，沿证据找到相关资产。应用程序自身的故障走普通诊断；起草新指令走写作流程。

## 选择证据

- **复核已有诊断，包括 Doctor 自己的答复。** 读[复核诊断](./references/review.md)。从维护者拿到的原答开始，为证据不足的建议给出修正结论，以及能直接回答原问题的检查。
- **使用前检查资产。** 读[静态审查](./references/static-review.md)，从实际包的入口走到交付物。遇到重复规则，分别判断能否合并两处写法、能否删去最后一处提示。
- **找出反复返工的原因，或解释一次偏差。** 读[会话证据](./references/sessions.md)。复盘从独立会话开始；排查一次偏差从原请求和交付物开始。
- **解释用量、上下文开销，或判断一份资料值不值得留。** 读[使用证据](./references/usage.md)。统计本该使用它的机会，把描述在场和正文读取分开。判断某段指令是否改变了模型原本的做法，也用这份指南。

先只读能直接回答问题的一个分支。单场会话里的重复读取归会话分支；另有成本、覆盖或价值问题时，再读使用分支。取证时直接打开维护者给出的路径及范围内的引用。缺少材料时，报出缺哪一份，在给定范围处停止追查。上级目录和其他会话是另外的数据来源。

## 提出处置建议

首项建议写证据已经支持的决定。**先调查**就是完整的维护建议：保留原文，指出下一项观察。即使维护者问“应该改什么”，也要先判定资产是否有缺陷。逐项指出受影响的任务、资产和证据，按对应分支给出的格式作答。证据支持处置时，再选动作：

- **保留**仍在适用场景中发挥作用的资产。恢复流程可能很少用，少数几次恢复就值得保留它。
- **改为手动触发**适合用途仍在、维护者能识别时机，且自动发现占用上下文或造成误调用的情况。写明该宿主中仍可使用的命令、名称或路径。
- **剪枝**时指出具体段落。短版本应在目标任务和模型上保留必需的行为。说明要保留哪项行为，哪个目标模型仍需要这段提示。
- **移除**适合用途已消失或已转移的资产。指出接替其用途的入口，核对还有哪些地方引用原资产，再建议移除。
- **修正**有证据表明存在缺陷的资产。错误交付能定位偏差。要判断该改指令、引用、触发条件、宿主设置、hook 还是评价器，还要查清它怎样造成偏差。保留交付中做对的部分。

不同处置仍各有可能时，指出最少还需观察什么，以及不同结果会怎样改变建议。把维护建议交给维护者。修改、删除、启动新的使用方实测、安装和发布各自需要授权。
