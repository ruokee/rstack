# 会话证据

## 找出重复问题

按获准的项目、时间和会话范围分析。逐场对照原请求与交付物，记下决定性证据的位置。从以下方面检查：

- **效率：** 用户为了什么又说了一遍？哪个动作反复执行，期间既无新信息，也没让任务往前走？
- **质量：** 交付物漏了哪条要求？对代码，查实际改动或适用的验收结果。遇到低分，回到产物核对评语。
- **资产使用：** 哪条指令在当时可见、被选中、注入、读取或实际执行？指出相关的 prompt、hook、步骤或资料，以及可观察的效果。

跨独立会话归并同类偏差。报告适用会话数、受影响的会话数，以及出错案例和可比的成功案例。同一场内的重复事件按次计：一场评审三次读取，计三次读取、一次受影响的评审。对照各场在关键决定上实际做了什么。如果失败和成功的评审都读过同一份 prompt，先保留它，查两场的动作为什么不同。

## 定位一次偏差

1. 对照原始预期和实际交付物或动作。指出用户看到的差异，也保留 Agent 做对的部分。用交付物、命令结果或验收规则核对评语。若证据与评语冲突，纠正评判。
2. 重建相关步骤。记录可查的宿主、模型、语言、实际版本或路径。区分磁盘上有文件、当次可见、被选用、注入或读取、实际动作、最终产物。宿主可能直接注入指令。只有最终答复时，加载情况记为未知。
3. 找到最早可观察的偏差。引用与请求冲突的步骤或产物，保留做对的部分。判断中途是否有其他动作时，先问哪份记录会捕获它。覆盖已知时，按记录判断；覆盖未知时，该动作是否发生也记为未知。观察区间两端的产物一致，只说明两次看到了相同结果。
4. 对每份比较材料写明**哪些条件一起变了**、**这次比较能判断什么**。点名调用归入选用后的行为证据，排除在自然选用率之外。多个条件同时变化，结果归于这组组合；各自作用记为未知。只有某项观察能够区分剩余原因，才有依据排列原因的可能性。

按能改变哪项决定选择下一项检查。文件有差异，就把对应段落列为待比较的对象。在相同加载条件下，对照原文与只改该段的试验副本，观察到必需行为改善后再采纳。原条件重跑能看偏差是否再次出现。如果两个原因都能导致复现，这次重跑仍区分不了二者。查自然选用时，用自然请求，带上措辞接近却应绕过的例子。

## 决定该改什么

每处偏差按**可见偏差 → 处置 → 证据或下一项检查**作答。先问：_如果逐字遵循当时的指令，还会按指令做出这个错误结果吗？_

- **照指令做会出错。** 引用有误的原句和实际遵循它的动作，修正该处。若评价器的评语与正确交付冲突，修正评语。
- **指令已要求正确动作，或关键原文不详。** 首项处置写“保留[资产]原文，原因待查”。指出现在要纠正的是哪项执行动作或交付，再写能定位资产缺陷的最小检查。可能的改写只放在检查结果对应的条件里。若同条件对照中只改变措辞便恢复了必需行为，就有依据建议在该场景采用改写。
