# 使用证据

## 确定计数口径

针对当前资产和时间窗，先查宿主记录了什么、覆盖哪些事件、什么任务本该用到它。按问题选择事件：

- **Skill：** 分开统计候选描述的呈现、选用和正文加载。评估发现能力时，区分点名调用和自然选用。
- **附带资源：** 分别统计每份资源的读取次数，以及读到它的适用任务数。用资源的读取条件确定适用任务。许多次 Skill 调用中只有一次迁移任务，那次读了迁移指南，指南对迁移任务的覆盖就是 1/1。
- **`AGENTS.md`：** 查宿主在哪个范围注入了哪些内容。仓库中的文件说明磁盘上有什么。
- **Prompt：** 统计可识别的调用或展开。两种事件对应同一次使用时，只计一次使用。
- **Hook：** 按时间窗分列匹配事件、已确认执行和执行状态未知的事件。执行记录属于产生它的事件。核对去留时，按下文“判断停用的影响”检查对应产物。
- **Playbook：** 识别哪次选用了流程、哪次进入了相关步骤。读取流程链接的例子单独计数。

报告计数时写明单位、时间窗、分母和记录覆盖范围。事件量计每次读取，覆盖率中每项任务或会话只计一次。记录在整个时段都会捕获该事件时，才可以报告零次。缺少事件记录时，次数记为未知。适用任务数为零时，报告该数量，使用比例记为不适用。

比较相当的时段和任务群体，同时给出绝对用量和适用任务的覆盖比例。前期八次发布全都调用，后期两次发布也全都调用，减少的是发布次数。若后期八次发布只调用两次，就去查另外六次是漏了必要步骤、换了入口，还是已能直接完成。解释下降趋势前，核对记录方式有没有变化。

## 核算上下文开销

按宿主实测分项报告上下文：描述按注入计，正文按加载计，每份资源按读取计。写明时间窗内各项的单次大小、次数和小计；大小不同时逐次相加。缺少 token 实测时，直接报告字节数，或说明 token 估算依据。计费用量要查账单数据。

判断是否跳过一份资源时，比较同一任务读与不读时的上下文用量，两者之差才是**资源新增开销**。如果两种情况下都加载了描述和正文，这两项在差值中抵消。分别报告资源新增量、完整读取路径的用量和时间窗总量。

## 判断对任务的影响

即使另有对照材料，也要给常规记录单独一项结论。开头用一行写：**常规记录：适用覆盖＝……；资源新增开销＝……；对任务的实际效果＝……**。日志只有读取，缺少决定、产物或返工时，最后一项填**未知**。然后逐组写补充材料的结论，某组有帮助或有害就归在该组。难题可能既更常查资料，也更容易失败。

决定一份资源的去留时，优先用已有可比材料：任务、模型、宿主、Skill 版本及其余资料相同，只改变这份资源是否可用。判断能否删去一段文字时，对照原文和只删去该段的版本。逐个目标模型检查交付结果、必须保留的行为和人工返工。

- **有帮助：** 资料补全了必需步骤，或省去一次纠正。指出具体决定和结果。
- **无明显差异：** 可比的交付满足相同要求，返工量也相近。说明比较条件和额外占用的上下文，只在这个范围内建议跳过或删减。
- **有害：** 遵循资料引入了具体错误，例如采用了另一个版本的说明。指出有问题的段落和后果。
- **证据不足：** 只留下读取记录，或多个条件同时改变。指出能区分解释的最小比较。已有材料不足以作答时，再建议新的实测；执行前取得授权。

## 判断停用的影响

先分清两个问题。追查**当次来源**时，把同一事件的原始输入、实际写入和最终产物对应起来。执行记录说明该步骤跑过。配置能定位写入通道，缺少返回正文时还要查实际写入。判断**停用后的结果**时，则查同一任务在已确认启用和停用条件下的合格交付与返工。即便已查明某次产物是谁写的，停用后的结果仍要单独判断。

审查现有对照时，在结论中点名每个拟用的样本及其状态。未采集执行事件的样本归为“未知”，即使能拿到成品也不能放进停用组。找不到已确认停用组时，处置是暂留；给出一组能回答去留问题的对照。

选一份确实需要该步骤发挥作用的输入，例如给格式化步骤一份尚未格式化的稿件。同一输入、执行者和其余配置，A 启用且确认执行，B 停用且确认生效。给维护者的判定规则从任务的验收条件出发：

- A 交付合格，B 漏项、写错或需要更多人工修订：保留该步骤，说清它保住了哪项要求或节省了哪道工序。
- 两份交付都合格，且 B 的人工修订没有增加：仅在这类任务上考虑停用。建议全局移除还要确认其余适用场景和引用。
- 两份都不合格：先查共同失败。只有 B 合格：查启用的步骤在哪处引入错误。缺少合格性或返工记录：维持暂留，并说清缺哪项观察。

用本案的实际交付要求写判定规则。两份产物一样可能是同样出错，也可能是有人替停用组补了工作；单凭相同就建议移除，应改写这条建议。
