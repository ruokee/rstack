# 方法有效性

检查方法能否提供预期决定所需的事实及区分。根据误判后果及方法中的不确定性，选择案例及检查深度。

## 追踪判定

沿一次完整使用过程追踪有意义的判据：

1. 从要求、已接受样例、协议、独立计算或用户明确决定中找到依据。
2. 确定使判据可观察的输入和条件。
3. 执行操作，保留相关输出、状态、测量或人工观察。
4. 应用约定的比较或评定方式，解释结果。

当前实现行为可以用于调查。预期行为以适用依据为准。快照需要有接受依据，才能成为参考结果。

从真实入口检查方法，按需观察准备、执行、结果读取及清理。检查运行错误与成功评定能否区分，以及观察是否对应预期对象版本和运行。

## 检查区分能力

选择能够暴露方法重要错误的案例：

- 已知正确案例检查可接受行为是否取得相应结果。
- 已知错误案例检查方法能否检出相关违规并指出位置。
- 合法变化检查无关顺序、措辞、格式及其他允许差异是否引起误报。
- 边界或反例检查可能使所选判据产生误导的前提。
- 对照检查步骤是否响应它声称测量的变量。

按不确定性选择案例。固定案例数及任意阈值会增加义务，却缺少对用途的支持。方法漏判案例时，在输入准备、执行、观察或判定中定位错误，修复后复查该路径。

对于比较两份导出的检查器，可以用一对有效数据，以及一对包含某个必要值变化的数据检查比较能力。明确约定顺序无关时，重排有效导出，检查工具是否仍然接受。这些条件仅属于该示例的合同。

## 校准波动判断

存在测量波动时，记录单位、负载、环境、采样方式及对照条件。根据当前决定的要求和实际波动选择重复次数及容差。调查差异来自对象还是测量条件变化。

人工评定需要定义参与者角色、任务、评分标准及相关现场条件。用有依据的样例解决理解分歧。模型评分需要保留理解结果所需的模型、提示、上下文、输入、输出及评分指引。将评分与结果有依据的专家判定比较。波动影响决定时，安排重复试次。

视觉或其他快照比较需要检查拟议基线，并说明接受理由。保持相关采集条件一致。更新预期结果前调查差异。

## 保留条件

模拟服务可以向客户端提供预设协议响应和故障。在一个构造示例中，stub 发送两个分块后关闭连接，使方法能够观察客户端的中断处理。记录预设分块顺序及客户端的要求结果。真实服务端时序和硬件执行需要各自环境中的观察。

分析模型需要附带假设、抽象、参数值及检查性质。有限模型检查按实际探索范围报告。用发现判断实现时，将模型状态和操作对应到实际对象。

将这些条件与结论放在一起，包括需要其他环境承担的部分。保留部分执行中的有用观察及其实际范围。

## 判断结果

区分证据形成的阶段：

- 成功执行表示步骤在记录条件下完成。
- 观察记录实际取得的事实。
- 判定依据明确判据评定事实。
- 判定受阻时，指出缺失条件及受影响问题。

对象违反判据时，保存失败案例和观察，交给其维护者。方法误判或难以取得所需事实时，在范围内修复方法。依赖、权限或运行能力阻碍执行时，记录实际失败、已完成覆盖及继续所需动作。

交付方法检查记录，说明对象及方法版本、所选案例、执行条件、实际观察、判定、修复和剩余要求。历史结果保留其取得时的条件。
