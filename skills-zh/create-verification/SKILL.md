# 创建验证方法

为具体验证问题建立方法，并提供使用方法所需的产物。对象可以是软件、数据、文档、配置、Agent 指引、实体设备或工作过程。按问题选择工作深度。

需要建立方法，或改变检查内容、操作方式及判定方式时，使用本流程。日常执行沿用已有方案。方案内的输入替换、命令拼装及临时辅助脚本仍属于该次执行。

## 调查对象

恢复当前请求、有效要求、相关对象版本、既有决定、可用检查、工具及权限。明确方法需要回答什么问题，以及本次是补齐缺失能力还是维护已有方法。

通过权威资料及可用工具查明能够调查的事实。向用户询问剩余的未决问题。区分要求行为、观察到的行为及仍需决定的期望。查明既有方法实际观察什么，以及由此留下的缺口。

问题及能力缺口在当前资料或观察中有具体依据后，进入下一步。

## 形成约定

提出能够回答问题的范围。说明哪些选择会改变结果的用途、成本或含义。与用户解决实际未决问题和重要取舍，包括拟议操作所需的权限。沿用有效决定。

按既有约定，将共识保存到对象或所属任务的资料中。按当前需要记录范围、判据及来源、方法及产物、使用寿命、执行条件、保存位置、操作入口、完成标准和维护责任。小任务可以只保存一段简短说明。在开展依赖工作前解决缺失的决定。

建设范围及判定依据明确，接续者能够恢复共识后，进入下一步。

## 选择方法

选择取得相关事实的方式：检查对象、实际执行、通过模型分析、比较受控条件，或安排人工评定。问题需要多类证据时，组合使用方法。

复用已有能力。识别缺少的输入、操作、环境、观察、判定或说明，再选择最小充分的产物。带结果解释的查询或人工操作步骤可以完成任务。需要比较方法、产物职责或使用寿命时，读取[方法选择](./references/method-selection.md)。

所选方法能够回答问题，每份必要产物的作用明确后，进入下一步。

## 建设方法

在当前权限内创建或更新约定的说明、程序、规则、案例、数据、环境配置、观察工具或评定辅助材料。技术工作按需使用对应领域指导。命令及配置引用其权威位置。

将输入、预期结果来源、执行条件和结果解释与方法放在一起。按需安排资源归属、结果保存及清理。在移除临时资源前保存值得保留的证据。

维护时读取[维护方法](./references/maintenance.md)，沿当前变化追踪受影响的判据、操作及产物。产品改动遵循所属任务及其权限。

产物能够支持约定的操作和判断后，进入下一步。

## 检查方法

按约定范围及权限实际使用方法。检查操作是否可行、观察是否对应问题、判定是否符合依据。按需选择已知正确及错误案例、反例、对照或人工校准。需要确定如何检查方法是否有效时，读取[方法有效性](./references/method-validation.md)。

将模型假设和模拟条件与其支持的结果一起保存。出现失败时，判断是对象违反要求、方法存在缺陷，还是执行条件阻碍判定。修复方法缺陷后复查受影响路径。保留受阻范围、实际原因、已完成结果及继续所需条件。

方法的用途有相称证据支持，每项结果说明实际覆盖范围后，进入下一步。

## 交付入口

提供方法位置、适用范围、前提条件、操作步骤、结果解释及必要维护信息。将共识、重要选择和方法检查结果保存到后续使用者能够找到的位置。

产物归对象或所属任务维护。Agent 需要独立发现和按条件读取时，可以提供对象专用 Skill。该 Skill 可以指导日常验证。本通用 Skill 负责方法建设及维护。

接手者能够找到并使用方法、理解结论及剩余条件后，完成工作。后续执行反馈作为未来维护的依据。
