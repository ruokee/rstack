# 已有模型

模型造成故障、含义难以辨认，或反复增加改造困难时使用本分支。先取得原因依据，再选择替代方案。先完成约定范围的完整目标设计，再划分实施批次。具体应用见[批量导入案例](./worked-example.md)。

## 追踪困难

从实际故障或具体的反复维护问题进入。记录必需行为及其来源、实际输入、受影响操作和后果。沿构造、转换、存储、恢复及消费追踪值，在相关位置指出所用含义、声明表示及背后的权威事实。

保留一个正常用法作为对照。例如，有行数据的导入成功可以正常处理，零行成功却得到不同解释。用同一业务合同对照这些路径。

宽泛字典、`Any`、强转、可选字段和重复解包是调查线索。成立问题需要已确认需求内的实际后果。动态键和真实位置协议可能正是合适的模型。

问题及有效对照路径能够沿受影响用法追踪后继续。

## 比较原因

按证据区分相关解释：

- 模型合并了概念，或允许消费者需要反复解释的组合。
- 某个局部实现错误处理了本已清楚的模型。
- 转换丢失了生产者提供的信息。
- 检查器难以表达或推断运行操作已经维持的关系。
- 数据本身确实具有开放或动态形状。

选择能区分主要解释的观察。原因在序列化之前存在、之后消失时，检查适配器。多个消费者对同一空载荷赋予不同含义时，比较分支和结果合同。判断保留模型、修复转换能否解决原操作的问题。

分别解释当前机制和最初选型原因。历史目标与约束根据记录归属。指出今天仍使模型持续存在的协议、调用者或存量数据，再按当前需求判断其适用性。深入历史推理时使用 `thinking-method` 的 `references/why.md`，比较故障机制时使用 `diagnose`。

原因能够解释失败和正常对照，重要替代解释得到处理后继续。有依据地保留模型也是有效结果。

## 完成目标设计

用[类型设计](../SKILL.md)的通用过程覆盖本次范围内全部相关用法，形成完整目标。包括：

- 类型含义、身份、值相等性、状态、缺失信息、关系及所需能力。
- 调用者操作、合法组合、结果及错误。
- 构造、解析、恢复、修改及维持保证的机制。
- 内部、传输、持久化及投影边界，包括 schema 归属。
- 每项旧新映射、拆分、合并、删除及信息缺口。
- 外部义务、历史读取、受影响的生产者及消费者、相关资源成本。

分别说明表示改善、业务理解纠正和政策变化。将已确认行为保留在映射中。单凭历史观察，无法建立保留错误的需求。

历史信息缺失时，记录缺口及解决它所需的权威来源。新值只从可追溯事实推导。事实仍缺失时，通过约定错误或解决流程暴露该情况。默认值需要业务依据。新增必填字段本身没有为其历史取值提供证据。

完整目标覆盖每项受影响操作和表示后继续。实施发现新事实时，更新受影响的设计和批次。

## 按可用操作分批

需要深入追踪直接调用者、动态用法、存量数据或部署关系时使用 `blast-radius`。沿实际依赖划分目标，每批包含相关类型、生产者、消费者及边界转换。

每批说明：

1. 起始表示及目标表示。
2. 权威数据及更新责任。
3. 共同改变的生产者、消费者和转换位置。
4. 中间状态必须保持可用的路径。
5. 完成证据及切换后移除的旧路径。

能够共同交付的调用者一起切换。独立发版或仍有效的历史协议可能需要过渡。将过渡限制在真实边界，明确负责人、转换方向及移除条件。长期外部协议适配器随协议继续保留。

表示共存时，明确权威写入方和同步责任。代码、已写数据和外部效果分别判断信息损失与恢复。保留实际恢复方法所需的事实。

每个中间状态都有连贯的生产和消费，各批能够抵达完整目标后继续。

## 完成改造

获准实施时逐批迁移，回到原操作检查。复用已有检查，更新合同发生变化的部分。比较有效输入、有意义的边界、错误、状态、顺序、序列化、历史恢复及相关成本。静态与运行依据覆盖不同性质。遵循当前工作流的验证分工。

仅请求设计时，交付可实施目标及批次计划。仅请求诊断时，交付有依据的原因及必要修复范围。

完整改造在以下条件满足时结束：范围内所有生产者和消费者采用目标，受影响文档和检查一致，失效类型及别名已经移除，临时转换达到移除条件，原问题在真实路径上解决。继续保留服务于已确认外部合同的适配器。
