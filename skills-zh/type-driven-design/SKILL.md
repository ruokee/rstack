# 类型设计

设计能够说明值的含义及调用方式的类型。从一次操作出发，推导它需要保留的区别，选择让字段和调用表达这些区别的表示。静态检查约束语言和当前工具配置能够支持的关系。

明确请求终点：分析、可实施的设计、审阅或获准改造。沿用已确定的需求和项目约定。调查会改变模型选择的缺失业务事实。单纯补注解和配置检查器沿语言或质量指导处理。模型的含义或组织存在困难时使用本流程。

## 从操作开始

读取需求、代表性调用者、已有类型及相关边界。用输入、结果和后续动作描述一次操作，明确当前困难、范围及需要保留的行为。

处理已有模型时，先读[已有模型](./references/existing-models.md)，取得原因依据后，再用下列通用步骤完成目标设计。选择 Python 表示时读取 [Python](./references/python.md)。需要具体推导或迁移示范时读取[贯穿案例](./references/worked-example.md)。

操作、受影响用法、必需行为及请求成果明确后继续。

## 识别区别

写出操作需要区分的事实，按问题选择相关维度：

- 身份与值相等性，单位，以及底层表示相同的不同参数角色。
- 共同存在的字段，互斥结果，状态及各状态允许的操作。
- 未提供输入、明确清空、待取得数据、缺失、失败和空的成功集合。
- 输入输出之间的关系，消费者所需的能力。
- 权威事实、派生值、历史快照、可变对象及修改责任。

为每个区别找到使用点。批次标识和来源标识被交换后会指向错误对象，因此需要区分。两个同类型账户参数仍需用名称说明角色。选择存在性判断之前，先解释零计数的含义。

每个必要区别都有操作含义后继续。未决事实与受其影响的选择放在一起。

## 选择表示

先写出预期调用方式，再选择让它可读的最小表示：

- 组成一个值的具名角色使用记录。
- 按实际键查找，以及动态键值集合，使用映射。
- 顺序或重复元素有意义时使用序列。保留真实的位置协议。
- 各情形具有独立载荷和处理方式时使用变体。
- 交换相似值会造成真实错误时，使用独立值类型。
- 泛型保留调用者依赖的类型关系。能力接口说明消费者的需要。

让字段、构造和操作解释同一组概念。传输、持久化、内部模型及查询投影在含义、生命周期或合同不同的位置分别表示。已有 schema 持有形状时，明确其他表示的生成或同步方式。

只比较具有实质取舍的方案，包含保留当前形式。考虑调用点的隐藏约定、变更范围、转换、分配、复制及存储布局。性能判断依据实际表示和工作负载。移除名称或转换没有增加有效区别的包装。

每个新增类型或转换都有具体用途，代表性调用能够解释操作后继续。

## 定位保证

为每项必要性质指出建立和维持的位置：

- 静态检查按语言和检查器配置约束带注解且纳入检查的用法。
- 构造和解析建立实际路径检查或推导出的性质。
- 转换和恢复保留已知信息，暴露事实缺口。
- 更新和所有权维持会受修改或共享别名影响的性质。
- 能够取得外部事实的操作负责存在性、并发、持久化及外部效果。

追踪普通构造器、工厂、解码器、历史读取及更新路径。经过检查的工厂为它的输出建立性质。将该性质归于所有实例之前，检查其他公开构造路径。

分别判断字段冻结、只读接口、深层不可变和独占所有权。状态快照描述该值。合法转移历史及已完成的外部效果需要各自的机制。

在真实边界及建立不变量的操作中安排运行时检查。内部调用者可以依赖已经成立的前提。说明保证范围及调用者仍需承担的责任。

每项保证都有机制、覆盖路径及明确限制后继续。

## 检查用法

回到原操作，检查有效边界、错误用法和一次相关变化，例如空成功、交换标识或增加结果分支。预期结果来自已确认合同。

将类型与调用放在一起阅读。读者能否解释各值的角色？分支是否对应真实情形？消费者是否反复从键、位置或标志中恢复规则？使用项目适用的检查器和运行方法，各自检查其能够建立的性质。遵循当前工作流的验证分工。

重要用法得到具体说明，保证有相称依据，剩余取舍明确后继续。

## 交付结果

按请求终点交付，在项目既有材料中保存模型含义、关键调用、保证位置及重要未决问题。已有模型还需包含[已有模型](./references/existing-models.md)中的原因、完整目标、旧新映射及连贯迁移批次。

获准实施时，将类型与生产者和消费者共同迁移，同步受影响的检查和文档，切换后移除失效内部路径。设计请求交付可实施的设计。分析请求交付有依据的结论。

约定范围完成，接手者能够解释模型、使用操作并找到保证依据时结束。

## 专项指导

问题需要详细知识时使用以下入口。类型选择继续由本流程负责。

- 概念或业务规则存在冲突：`domain-driven-design`。
- 模块职责、接口或依赖：`code-design`，重点为 `approaches/data-modeling.md` 和 `interfaces.md`。
- 历史选择或持续原因：`thinking-method` 的 `references/why.md`。竞争故障解释：`diagnose`。
- 消费者、存量数据、部署或恢复影响：`blast-radius`。
- 转移历史、并发或时序性质：`statechart`。
- 质量判断或检查器设置：`code-quality`。创建或维护验证方法：`create-verification`。
- 语言或库机制：`python-engineering`、`msgspec` 或相应语言指导。
