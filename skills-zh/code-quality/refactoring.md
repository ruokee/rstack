# 重构风险

重构调整结构，同时保持外部可观察行为。依据项目契约明确值、错误、事件、持久化结果、顺序、资源所有权及已声明的成本上限。有意的行为修正拥有自己的变更契约。

## 行为证据

证据需要匹配风险。编译及类型检查覆盖其支持的静态关系。测试覆盖实际输入及断言。可重复运行可以比较输出、副作用及失败行为。固定套件保持绿色的价值取决于其保护的契约。

特征描述记录当前行为。已知错误按行为变更讨论。证据缺口需要具体落到有风险的变换或保证，是否补充证据、调整范围或延后变换由当前流程决定。

小变换有助于定位回归及局部推理。检查节奏、测试创建、提交、回退及部署沿用当前任务。本参考提供判断候选所需的风险依据。

## 提取函数

核对输入、返回值、变量写入、别名、控制流及错误传播。提取后的 `return`、`break` 或 `continue` 可能指向不同目标。闭包可能观察稍后的值，资源作用域移动可能改变释放时机。

提取应表达完整责任。传递大量可写局部变量，或仅为拼回原控制流而返回一组值，说明边界仍需判断。完整结构方案见[改进既有代码](../code-design/existing-code.md)。

## 内联函数

比较参数求值次数、顺序及时间。将有副作用的表达式替换到参数的每个使用位置，可能重复 I/O 或状态变更。还需核对短路、捕获状态、递归、重载解析、动态分派及局部名称冲突。

以下完整 Python 3.11+ 示例保持一次 `read_value` 调用。契约是源数据只读一次，结果为该值的两倍：

```python
def run():
    reads = []

    def read_value():
        reads.append(1)
        return len(reads)

    def double(value):
        return value + value

    original = double(read_value())
    assert (original, len(reads)) == (2, 1)
    reads.clear()
    value = read_value()
    inlined = value + value
    assert (inlined, len(reads)) == (2, 1)


run()
```

替换成 `read_value() + read_value()` 会产生 `3`，并读取两次。临时变量承担保持求值的责任。

## 移动行为

比较规则归属、所需状态、可见性、依赖方向及调用负担。代码移动可能改变导入、初始化顺序、依赖环、注册、反射、动态查找及序列化名称。源代码引用只是消费者契约的一部分。

独立发布的消费者或发布义务可能需要兼容转发及明确移除条件。项目整体清洁切换要求全部受影响调用方及旧路径满足所选迁移契约。审查核对普通调用方、动态引用及文档，再报告遗漏位置、后果及修复方向。实际修改沿用独立的任务授权。
