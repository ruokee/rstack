# 代码质量

依据项目已确认的契约、约束和质量目标检查代码、测试及代码设计。质量工具需要明确其检查能力及生效范围。当前任务提供范围、权限、输出格式和工作流程。

## 证据

- 发现对应具体的契约违反或实际维护成本。代码说明当前行为。认定某条路径正确，需要该路径已确认的契约。原则名称、代码行数、实现数量和个人偏好只是调查线索。
- 区分直接观察到的事实、推论、判断及建议。行为发现需要契约内的反例，给出合法输入或执行、要求的结果及实现或设计推导的结果。反例保持题设定义及已确认前置条件。维护问题须说明当前使用、真实变化记录或已确认下一项改动中的实际成本。
- 核对最相关的反证，例如已建立的前置条件、包装承担的转换责任，或本身属于契约的交互。反证改变结论时撤回或收窄发现。
- 代码摘录中给出的声明及协作者契约定义了该示例中的实体。额外的外部行为及模块归属须依据已检查的来源或已确认契约。复现程序说明其设置下的行为，设置中的假设需要独立依据。
- 零问题结果有效。同一原因的多个表现合并说明，保留执行修复所需的位置及不同后果。

## 参考

按当前问题读取对应参考：

- 边界包装涉及单位、错误或表示转换时，先读取[结构质量](./structure.md)及[适配器](../code-design/design-patterns/adapter.md)，再判断转换责任。在 OMP 中使用 `skill://code-design/design-patterns/adapter.md`。
- 值、错误、状态、资源、并发或设计承诺的行为，读取[正确性](./correctness.md)。
- 职责混杂、共同规则重复、耦合、无效间接层或变化成本，读取[结构质量](./structure.md)。
- 断言、期望值、行为覆盖或测试先行反馈，读取[行为测试](./testing/behavior.md)。
- 时间、顺序、共享状态、外部资源或并发测试，读取[测试可靠性](./testing/reliability.md)。
- 脆弱断言、晦涩夹具、重复测试或低价值覆盖，读取[测试维护](./testing/maintenance.md)。
- 审查涉及求值、状态、所有权、导入或调用方变化的重构或迁移候选，读取[重构风险](./refactoring.md)。
- lint 规则、生效文件、例外或自动修复，读取 [lint 设置](./tooling/lint.md)。
- 类型检查范围、严格度、动态边界或类型逃逸，读取[类型检查](./tooling/type-checking.md)。

只读取当前判断所需的参考。同一问题可以涉及多个专题。参考中的设计链接指向同语言 `code-design` 包。在 OMP 中，取链接目标中 `code-design/` 之后的部分作为 `<path>`，使用 `skill://code-design/<path>` 直接读取，例如 `skill://code-design/approaches/resource-lifecycle.md`。按每份已加载参考中匹配的条件读取所需设计叶文件，随后沿用当前检查的输出格式及权限。形成完整替代结构时使用 [code-design 入口](../code-design/SKILL.md)。资源缺失时报告具体路径及受影响判断，继续完成有依据的部分。

## 结果

沿用调用方要求的格式。普通审查先给成立发现，将每项内容归为成立发现、澄清问题或检查覆盖。发现的必要前提得到支持后，给出位置、有依据的触发条件、影响及最小充分的修复方向，并标注严重度和置信度。严重度描述后果，置信度描述证据强度。缺失前提的答案影响范围内判断时，列为澄清问题，给出缺少的事实及受影响判断。已满足的契约及契约外输入归入检查覆盖。修复建议对应成立发现。整份报告采用相同分类及发现标准，包括摘要及修复建议。零问题结果说明对象、覆盖范围及实际执行的检查。

工具诊断保留工具来源及原始位置。合并重复诊断，补充相关契约或修复取舍。用户专门要求 lint 或类型检查结果时直接报告对应诊断。

质量设置请求需要说明目标问题、选用检查、生效文件、严格度、例外、诊断含义及验证方式。现有缺陷与建议采用的约束分别说明。

检查、建议和实际修改各自沿用当前任务授权。应用修复、修改配置、创建测试和调整结构需要对应权限。迁移审查报告遗漏调用方及残留路径，实现应满足的清洁切换义务作为判断依据。
