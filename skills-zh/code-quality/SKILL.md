# 代码质量

依据项目已确认的契约、约束和质量目标检查代码、测试及代码设计。质量工具需要明确检查能力及生效范围。当前任务提供范围、输出格式和工作流程。

## 证据

- 发现对应具体的契约违反或实际维护成本。代码说明当前行为。认定某条路径正确，需要该路径已确认的契约。原则名称、代码行数、实现数量和个人偏好只是调查线索。
- 区分直接观察到的事实、推论、判断及建议。行为发现需要契约内的反例，给出合法输入或执行、要求的结果及实现或设计推导的结果。反例保持题设定义及已确认前置条件。维护问题须说明当前使用、真实变化记录或已确认下一项改动中的实际成本。
- 核对最相关的反证，例如已建立的前置条件、包装承担的转换责任，或本身属于契约的交互。反证改变结论时撤回或收窄发现。
- 代码摘录中给出的声明及协作者契约定义了该示例中的实体。额外的外部行为及模块归属须依据已检查的来源或已确认契约。复现程序说明其设置下的行为，设置中的假设需要独立依据。
- 零问题结果有效。同一原因的多个表现合并说明，保留执行修复所需的位置及不同后果。

## 参考

按当前问题读取通用参考，再按语言读取具体机制及可运行示例：

- 值、错误、状态、资源、并发或设计承诺的行为，读取[正确性](./code/correctness.md)。
- 职责混杂、共同规则重复、耦合、无效间接层、变化成本，或涉及单位、错误或表示转换的边界包装，读取[结构质量](./code/structure.md)。检查包装时，比较职责及源契约到公开契约的映射。
- 审查涉及求值、状态、所有权、导入或调用方变化的重构或迁移候选，读取[变更安全性](./code/change-safety.md)。
- 断言、期望值、行为覆盖或测试先行反馈，读取[行为测试](./testing/behavior.md)。
- 时间、顺序、共享状态、外部资源或并发测试，读取[测试可靠性](./testing/reliability.md)。
- 脆弱断言、晦涩夹具、重复测试或低价值覆盖，读取[测试维护](./testing/maintenance.md)。
- 格式化、lint 规则、自定义检查、生效文件、例外或自动修复，读取 [lint 设置](./tooling/lint.md)。
- 类型检查范围、严格度、动态边界或类型逃逸，读取[类型检查](./tooling/type-checking.md)。

只读取当前判断所需的参考。同一问题可以涉及多个专题。如果存在 code-design Skill，可参考其中的设计资料。本 Skill 中的 `code-design/…` 表示 code-design 内的参考文件。

## 结果

沿用调用方要求的格式，给出当前对象的代码质量分析结果，涵盖代码审查、仓库分析及质量工具设置。存在成立问题时优先说明，按证据区分每项内容：

- 成立发现需要建立必要前提，给出位置、有依据的触发条件、影响及最小充分的修复方向。严重度描述后果，置信度描述证据强度。
- 澄清问题询问范围内判断所需的缺失事实，并指出受影响判断。说明条件性后果时，显式保留每个尚待确认的前提。前提确认后，再提出修复要求、标注严重度及置信度。
- 检查覆盖记录已满足的契约及契约外输入。零问题结果说明对象、覆盖范围及实际执行的检查。

整份报告采用相同分类及发现标准，包括摘要及修复建议。

工具诊断保留工具来源及原始位置。合并重复诊断，补充相关契约或修复取舍。用户专门要求工具结果时直接报告对应诊断。

质量设置请求需要说明目标问题、选用检查、生效文件、严格度、例外、诊断含义及验证方式。现有缺陷与建议采用的约束分别说明。

检查及建议遵循当前任务范围。应用修复、写回配置、创建测试及调整结构需要对应授权。检查节奏、提交、回退及部署由当前任务安排。
