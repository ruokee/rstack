# lint 设置

依据具体质量问题及误报成本选择 lint 检查。实际行为来自项目配置、调用方式及锁定的工具版本。读取这些依据，再判断生效结果。

## 规则选择

区分格式、机械错误、语言语义及启发式维护规则。已有 formatter 负责格式。增加重复诊断前比较编译器、类型检查器及其他 linter 的重叠范围。

函数长度及复杂度阈值属于启发式。诊断需要结合[结构质量](../structure.md)中的契约及责任判断。工具严重度与审查发现的实际影响分别解释。

## 生效范围

确认命令工作目录、配置继承、覆盖、文件匹配、忽略项及工具版本。分别核对生产代码、测试、脚本及生成代码。显式文件参数的行为可能区别于目录发现。

严格度可以全局、分目录或通过明确基线采用。说明哪些文件及规则实际受检。基线是例外边界，其增长会影响保护范围。

## 例外

例外需要明确规则、最小有效范围及实际理由。生成代码的导入由生成器维护时，可以需要具体例外。广泛忽略可能隐藏理由之外的缺陷。说明抑制注释、文件排除及遗留基线如何影响覆盖。

自动修复具有不同的行为风险。依据工具分类及实际变更判断。不安全修复、扩大改写范围及批量抑制沿用任务授权。

## 验证

使用工具支持的配置展开或文件发现命令，再检查一项目标违规及其匹配的合法案例。记录生效文件、规则标识、诊断及退出状态。命令失败、文件被排除及零诊断具有不同含义。

以下独立 Ruff 示例只启用未使用导入检查。保存为 `ruff.toml`，生成文件例外表达项目已决定由生成器维护生成代码导入：

```toml
[lint]
select = ["F401"]

[lint.per-file-ignores]
"generated/*.py" = ["F401"]
```

违规案例保存为 `bad.py`：

```python
import math
```

合法案例保存为 `good.py`：

```python
from math import ceil


def page_count(items: int) -> int:
    return ceil(items / 10)
```

使用项目的 Ruff 可执行文件运行 `ruff check --config ruff.toml bad.py good.py`。预期仅 `bad.py` 产生 `F401` 诊断，退出状态非零。单独检查 `good.py` 应成功退出。使用该配置检查 `generated/api.py` 中相同的未使用导入时，应按例外放行。通过 `ruff check --show-settings --config ruff.toml good.py` 核对选用规则及例外。选项语法以项目安装的版本为准。
