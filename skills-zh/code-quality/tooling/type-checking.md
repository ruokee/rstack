# 类型检查

类型检查判断语言及检查器支持的静态契约。依据项目需要发现的错误选择范围及严格度。运行时输入合法性、业务不变量及并发协调各有对应机制。

## 生效检查

确认检查器、语言及依赖版本、目标平台、模块解析、受检文件及外部类型声明。按所选版本的帮助或文档核对严格度预设及默认值。项目现有严格度作为约束，建议调整时说明影响。

区分参数及返回值检查、可空性、封闭变体、泛型、动态值及无类型依赖。文件发现及依赖分析可能覆盖不同的文件。导入可能让发现阶段排除的文件参与分析。检查成功描述实际分析过的代码及关系。未分析的文件及未检查的函数体限制相应结论。

## 动态边界

追踪 `Any`、动态属性、cast、断言及忽略注释如何进入消费者。它们可能移除检查，或将义务转交作者。cast 告诉检查器采用什么假设。它不会在运行时校验外部值。

依赖缺少类型时，先核对是否存在匹配已安装版本的上游类型或 stub。本地声明需要真实 API 及应用实际用法的依据。编造方便的签名可能让检查器接受错误契约。小范围的缺失导入例外需要说明动态影响，全局抑制可能将其传播到无关代码。

受控构造及私有状态可以通过实际访问路径实施不变量。静态形状与这些保证的区别见[数据建模](../../code-design/approaches/data-modeling.md)。消费者边界见[接口](../../code-design/interfaces.md)。

## 采用范围

分模块采用或基线需要说明受检代码、采用的约束及保留例外的理由。全量收紧前比较诊断与目标错误。抑制需要记录规则、范围、理由及失去的检查能力。

## 验证

比较严格度时，保持版本、入口文件、导入选项及类型声明一致。在应被纳入的文件中引入一项目标静态错误，并保留匹配的合法案例。观察实际诊断、位置、严重度及退出状态。零错误可能来自文件被跳过时，单独核对文件发现及生效配置。

以下 mypy 示例针对 Python 3.11+ 的可空值误用。局部契约允许缺失标签时抛出 `ValueError`，存在标签时转为大写。违规实现保存为 `bad.py`：

```python
def label(value: str | None) -> str:
    return value.upper()
```

合法实现保存为 `good.py`：

```python
def label(value: str | None) -> str:
    if value is None:
        raise ValueError("missing value")
    return value.upper()
```

使用项目的 mypy 可执行文件运行 `mypy --strict bad.py`，应报告对 `None` 变体的不安全访问并非零退出。`mypy --strict good.py` 应通过。`good.py` 中的分支承担运行时处理，检查器判断其支持的静态关系。类型检查器不会增加运行时校验。

实际采用时使用项目支持的版本及配置。在应用真实边界核对缺失依赖类型及局部例外，包含 `Any` 如何进入消费者。说明仍依赖运行时检查或行为验证的属性。
