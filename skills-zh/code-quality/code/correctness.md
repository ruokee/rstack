# 正确性

正确性指在合法输入及执行条件下满足已确认契约。发现需要将具体实现或设计决定与可重现的值、状态转移、失败或允许的交错联系起来。

## 值

检查单位、精度、范围、空值、身份、顺序及表示转换。确认哪一方负责建立前置条件。调用方已经建立所需不变量时，可以构成相关反证。运行时校验遵循项目真实输入契约。

类型注解、不可变字段及命名约定各自提供语言机制支持的保证。宣称不变量保持前，核对构造、修改、别名及访问路径。已确认的单位或表示错误跨越边界时，在负责转换的位置统一处理，并保持契约要求的精度及舍入方式。深入表示设计可参考 `code-design/approaches/data-modeling.md`。

## 错误

检查成功、业务拒绝及基础设施失败是否保留消费者需要的区别。错误映射可能丢失重试资格、责任归属，或副作用是否已经发生的信息。请求发出后的超时可能留下结果未定的副作用。

约定支付接口分别报告业务拒绝及传输不可用时，映射应保持“业务拒绝到拒绝、传输失败到不可用”的区别。将两者都映射为拒绝，会丢失调用方需要的失败信息。恢复不同映射，并保留契约所需的原因信息。是否重试是项目的独立策略。深入边界设计可参考 `code-design/interfaces.md`。

## 状态

追踪相关的创建、修改及观察路径。检查过期快照、共享可变别名、多写者及非法状态转移。先检查、稍后写入，可能允许其他参与者使前面的检查失效。

多副作用操作需要指出每个失败点之前已经完成的动作及调用方获得的信息。数据库事务覆盖实际参与事务的资源。远程调用及消息需要各自已确认的完成语义。业务规则来自项目，缺失规则使具体判断保持待澄清。

交错执行使已检查条件失效时，将检查及更新放入同一受支持的原子操作、锁或事务中。所选机制应覆盖实际写入方及资源。扩大锁或事务范围可能增加竞争。部分完成时保持已确认的报告及恢复契约，按实际结果说明各项副作用。

## 资源

沿取得、部分初始化、借用、移交及释放路径，确认资源所有者及责任转移。检查错误、取消、清理失败及超出所有者作用域的任务。

迭代过程持有资源时，按实际协议核对耗尽、支持的显式关闭、提前退出、错误及取消路径中的释放责任。存在暂停或在途工作时，区分停止消费、关闭资源及取消工作。核对调用方能否继续持有暂停的迭代过程，以及它保留的资源。确定每项保证的所有者及实际完成动作。

已确认泄漏或过早释放时，将清理放入所有者作用域保证执行的退出机制，释放部分取得的资源，等待仍使用资源的工作结束后再释放。迭代过程持有资源时，修复需要明确实际协议支持的关闭或限定作用域使用契约，并核对调用方实际遵守。有意收集全部结果会改变内存占用及释放时机。深入生命周期设计可参考 `code-design/approaches/resource-lifecycle.md`。

## 并发

竞争问题需要给出合法交错及其后果。原子性、锁、事务隔离、取消及任务归属需要对应实际运行时。分别检查活跃操作、排队工作、保留结果及缓冲区的上限。仅在 I/O 周围使用 semaphore，仍可能产生无界数量的等待任务。

审查设计时比较其承诺及表示方式。输入规模无界时，返回前收集全部结果与有界流式承诺冲突。按数据源及消费者的需要，用增量产出、背压或有界 worker 队列修复已违反的上限。保持必要顺序及取消行为，限制保留结果可能改变延迟和调度。深入调度设计可参考 `code-design/approaches/async-concurrency.md`。

## 成本

分配、复制、重复 I/O、缓存增长及队列保留，需要依据已声明的资源或性能要求形成问题。说明输入规模及造成增长的机制。运行时间或吞吐量结论需要对应测量条件。区分从代码推导的容量判断及实测运行结果。

在负责位置消除已确认的多余复制或重复副作用，或按已确认要求限制保留量。修复需要交换不同资源成本时，依据相关负载比较内存、重复计算及 I/O 成本。
