# 先迁移再清理

使用方已经采用选定契约，旧契约的职责也已结束时，替换才算完整。两者都保持有效，会让后续修改同时承担两份责任。

例如，将指南迁到新入口，需要更新读者使用的链接、生成导航、例子及旧标题引用。发布新页面，同时让旧路径继续承担日常使用，会形成两个维护位置。

追踪实际消费，包括调用方、导入、配置、文档及行为检查。能够协调修改时，一起迁移这些使用方。在授权范围内，移除用途已经结束的接口、别名、适配器及说明。

外部客户端或已发布链接可能有真实兼容义务。明确需要支持的使用方、所需过渡方式，以及结束条件或复查日期。必需的重定向或适配器有具体职责。假设中的使用方无法提供这种需求。

行为检查应遵循已确认的新契约。预期冲突时，先根据契约判断，再修订检查或实现。只约束旧内部结构的检查可以随其退出。过渡期间的连续性参见[结果导向执行](./outcome-oriented-execution.md)。
