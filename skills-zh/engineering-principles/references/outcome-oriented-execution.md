# 结果导向执行

迁移需要清楚的完成状态。先明确目标行为及必须采用它的使用方，再按中间工作是否推进了完整结果判断进展。

例如，替换本地搜索索引，可能需要一起修改数据写入器、查询读取器及存储格式。在独立开发分支上，构建这项协调变更时，各部分可以暂时不一致。为该阶段限定范围并保留恢复点。在线搜索服务则可能要求查询持续可用，因此需要先构建独立索引，再在就绪后切换读取方。

运行契约决定哪些中间状态可接受。纳入真实兼容义务，为过渡机制明确退出条件。额外路径在保留期间持续产生成本。

完成既需要目标结果，也需要其承诺行为在相关条件下的证据。根据承诺和风险选择最终检查，由当前任务指定的角色执行。

使用方迁移参见[先迁移再清理](./migrate-then-clean-up.md)，后续工作依赖中间结果时参见[验证后再推进](./verify-before-advancing.md)。
