# 边界纪律

每项检查都应有负责的位置，以及它要建立的性质。边界是操作接收另一份契约管理的表示的位置，例如配置文本、请求或存储记录。

配置超时值的解析可以确定单位及非负值域。在这些性质持续有效时，后续计算可以直接使用它们。同一配置还可能指定文件。文件的可用性会在解析后变化，打开文件时仍需处理真实 I/O 结果。

将转换与基于已接受模型的决策分开。含义允许时，计算独立于框架访问。外围协调负责 I/O 并传播真实失败。在接收位置返回输入错误，提供说明被拒绝内容所需的上下文。

反复检查已经确立且未变的性质，会增加维护工作。性质会变化时，再进行检查或同步：共享余额、可变别名、历史记录或其他构造路径可能需要不同的保证。内部产生的数据也按同样方式判断。

对外提供使用方需要的模型。传输和框架细节由适配器维护，公开契约明确包含它们时按契约处理。构造保证参见[类型系统纪律](./type-system-discipline.md)，可变状态归属参见[共享前先隔离](./isolate-before-sharing.md)。
