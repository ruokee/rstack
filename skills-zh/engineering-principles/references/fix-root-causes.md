# 修复根因

因果修复会改变产生契约违约的机制。从报告的行为、预期结果及已有证据出发，保留解释差异所需的输入和条件。

下载可能显示成功，却留下截断文件。隐藏失败会保留不完整结果。追踪字节数及写入循环，可能发现部分写入被当成完整写入。修正这种判断，才能恢复承诺的输出。接受无效输入是契约首次失效的位置时，输入校验也可以是正确修复。

沿相关状态转换及依赖追踪。多种解释都符合现象时，取得能够区分它们的观察。在授权范围内查找受同一错误规则影响的路径，并在规则所属位置修正。

故障与重启相关且有证据支持时，持久化状态及生命周期转换值得调查。清理状态后恢复，说明被改变的状态具有影响。更强的因果结论需要识别负责性质的观察。保留有用证据，破坏性清理取得所需授权。

缓解可以在调查继续时恢复运行。说明证据支持哪种结果，并按指定验证分工检查修复后的原始故障路径。连续修复保留可疑假设时，使用[质疑前提](./attack-the-premise.md)。
