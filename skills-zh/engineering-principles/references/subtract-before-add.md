# 先减后加

看似需要再加一套机制的问题，可能源于一条已经失去用途的规则。检查删除这条规则后，目标行为是否已经能够成立。

例如，一个命令曾支持两种执行引擎，因此有两个开关。现在只剩一种引擎，两个开关控制同一选择。增加优先级规则会保留相互矛盾的组合。移除多余开关可以直接消除歧义。

明确待删除内容还有哪些使用方，以及它保护什么契约。在获准的变更中删除失效部分，连同会指向它的引用一起处理。再根据简化后的结构判断剩余需求。

重复状态、透传包装、闲置分支及重复文档指令也适用同样的判断。保留读者仍需的条件和导航。保护真实契约的输入检查仍有用途。

简化后的结果满足目标时，删减就已足够。仍有需求未满足时，再补上对应能力。
