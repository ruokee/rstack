# 体验优先

实现选择会在作者和所有使用者之间分配工作。沿使用者的完整任务判断这种分配。使用者可能是最终用户、API 调用方、读者或维护者。

启动长时间导出的命令，需要说明调用方怎样取得最终结果。对于具备状态 API 的自动化客户端，返回任务标识可能足够。交互用户则可能需要可用的进度视图及清楚的输出位置。根据真实使用契约选择反馈。

从起点追踪任务中的决定、错误及完成过程，找出使用者需要猜测、重复工作，或重新拼出实现已经知道的信息的位置。文档需要检查前提及下一步是否出现在读者需要它们的地方。

这些成本与实现便利冲突时，优先考虑使用者。保留已确认的功能及约束。缩减范围或改变产品方向，由有权决定的人判断。

观察能够解决影响体验的重要疑问时，采用可丢弃原型。已有明确做法的选择可以直接执行。目标是为约定任务提供完整可用的结果。
