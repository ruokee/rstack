# 先造工具

工具在执行或审阅中省下的工作，超过编写、说明、运行和维护成本时，就值得采用。复杂的一次性工作也可能受益，因为可复现结果更便于检查。

例如，在生成的配置文件中批量重命名字段，识别语法的转换工具可以区分字段与字符串内的相似名称。先理解一项有代表性的转换，包括必须保持的内容。再为最小有用工具明确输入、输出及重跑语义。

大范围使用前，将工具结果与已理解的单位比较。一致的转换也可能一致地实现错误假设。检查所用的预期需要来自契约，与产生结果的机制分开。

根据眼前工作选择形式。查询或直接命令可能足够，重复转换可能值得保留脚本。其他人需要审阅结果时，保留重跑方法及解释。两处清楚的局部编辑可能直接完成更便宜。

需要约束已确立的反复规则时，使用[把教训落实到结构](./encode-lessons-in-structure.md)。本原则关注当前工作的成本及可检查性。
