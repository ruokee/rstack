# 把教训落实到结构

反复出现的错误可能揭示一条值得用机制约束的稳定规则。选择表达方式前，先明确规则范围及例外。

例如，翻译文档反复链接到错误语言版本。导航检查可以按仓库的语言配对规则检查各链接。覆盖程度取决于能否识别真实链接形式及合法例外。一概禁止跨目录链接，会施加另一条规则。

按何时能够知道该性质选择机制。类型可以表达构造约束，从 schema 生成的内容可以共享定义，lint 可以发现明确误用，运行时检查可以判断实时状态。元数据需要有实际读取并约束它的使用方。

比较所需覆盖范围、绕过路径、误报及维护成本。选择能提供所需保证的最简单机制。保留使用方需要的契约及解释。重复提醒的含义已经完整覆盖时，再删除它。

一次纠正提供调查模式的证据。模式确立后再推广。需要判断的规则继续使用清楚文字及有用例子。需要降低当前工作的执行或审阅成本时，另用[先造工具](./build-the-tool-first.md)判断。
