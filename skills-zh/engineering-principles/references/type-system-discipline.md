# 类型系统纪律

有用的类型能省去使用方原本需要重复作出的判断。从使用点出发：它必须区分哪些组合，哪些值会违反契约？

导入器可以返回 `Queued`、`Loaded { rows }` 或 `Rejected { reason }`，各变体携带使用方需要的信息。语言的检查器提供穷尽保证时，新增结果会在受影响的使用点显现。兜底分支可能掩盖这项变化。

基础表示相同、交换后含义会改变的值需要区分，例如行偏移量和行数。通过构造方式及参数类型保持这种区别。操作依赖额外精度时，其成本才有依据。统计空集合仍是有效操作，选出最大成员则需要显式空结果或非空输入。

构造过程需要真实建立所承诺的性质。用起点和长度表示区间时，需要约束长度非负，并定义算术及溢出行为。将不受限制的数改名为 `Length`，会留下这些义务。外部表示通过合适的[边界](./boundary-discipline.md)解析。运行时擦除的类型断言仅影响静态检查。数值转换按语言和操作判断值域变化、失败及溢出行为。

需要多种表示时，从拥有形状的 schema 派生。绕过构造入口及未经检查的转换会造成保证缺口。静态检查覆盖定义和构造路径实际约束的性质。可变别名、并发写入、持久化及外部效果需要管理其实际执行的机制。
