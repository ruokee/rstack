# 留出呼吸空间

在函数签名、持久化数据或测试把一个选择固定下来之前，问：今天谁依赖它？明天维护者换一种做法，谁得跟着改？既看书面要求，也看实际调用。文档以外的依赖也可能因改动而失效。

别人在一项保证上开展工作前，先把它定清。任务搬到新目录时，其他任务若按 ID 引用它，ID 就必须保持稳定。引用旧路径的链接则需要迁移。第一版只实现一种目录布局就够了；任务身份和存放位置各有各的用途。

答案取决于本次操作时，把选择留给操作者。例如，移动文件时，由操作者指定本次引用扫描要排除的目录。预览列出这些目录的名称，只扫描其余文件。范围是操作者的决定，命中的文件只是当时的清单。工具在首次写入前按同一范围重新扫描，范围内新增的引用可能使移动计划失效。排除目录无需打开，也无需统计其中跳过了多少条引用。

可以替换的做法留在实现里。列表若承诺按时间升序，测试就检查记录是否完整、时间是否升序。要约束同时间记录的次序，先看调用方怎么用结果。若调用方依赖这些记录保持输入顺序，就保留并测试这项行为。两种约定都把算法留给维护者选择。公开策略开关会把算法本身也变成承诺。
