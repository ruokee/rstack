# Skill 机制

这是 [writing-for-agents](./SKILL.md) 中专门讨论 Skill 的部分，涵盖 frontmatter、调用方式及路由 Skill。通用写作方法见 `SKILL.md`。

## 调用方式

对于支持 `disable-model-invocation` 的宿主，两种常见配置分别承担不同的负担：

- 模型触发的 Skill 向 Agent 提供 `description`，供其自动选择。用户也可以显式调用。description 是顶层上下文指针，通过上下文负担换取可发现性。纯参考型 Skill 可以保存多项 Skill 共用的材料。省略 `disable-model-invocation`，编写面向模型的 description，并列出不同的触发分支。指针写法遵循 `SKILL.md` 中的规则。
- 用户触发的 Skill 设置 `disable-model-invocation: true`，退出自动选择。保留面向人的 description，用一句话概括用途。用户或显式路由入口负责记住何时使用。

该字段对具名加载的影响取决于宿主。OMP 会从默认提供给模型的列表中隐藏这类 Skill，同时保留通过 `skill://` 按名称读取的能力。编写会导航到其他 Skill 的内容时，先核对宿主对显式加载和调用的规定。

需要 Agent 自主发现时，选择模型触发。由用户或显式路由提供入口，且宿主支持该路径时，选择用户触发。这样可以分别考虑自动发现和访问已知 Skill 的能力。

共用参考材料保留在一个可访问的位置。如果宿主限制跨 Skill 加载，将材料放到双方都能读取的普通参考文件中。

## 按调用拆分

当某个独立的引导词需要单独触发，或者其他 Skill 需要自主发现它时，可以拆出一项模型触发的 Skill。新增 description 会带来上下文负担，独立发现的价值应当足以承担这个成本。如果另一项 Skill 已经知道目标名称，先核对宿主是否支持具名加载，再决定是否增加自动触发。按执行顺序拆分的方法见 `SKILL.md`。

## 路由 Skill

用户触发的 Skill 多到难以记住时，可以用路由 Skill 列出各项名称及使用条件，使用户只需记住一个入口。宿主支持具名加载时，路由可以直接读取目标 Skill。如果宿主要求用户另行调用，路由则告诉用户下一步应当调用哪一项。
