# 组合优于继承

将复用实现和承诺行为可替换性分开判断。组合通过协作者、委托及函数组装行为。实现继承复用基类行为，同时将派生类型绑定到基类契约和扩展机制。

## 识别耦合

子类可能依赖基类调用哪些内部方法、调用顺序，以及调用时的状态。改变顺序可能破坏子类，即使基类的公开行为保持不变。这就是脆弱基类问题。

采用组合的所有者可以依赖协作者的显式契约，仍需定义归属、生命周期、错误传播及共享状态。边界实际容纳了相关知识时，组合才会降低耦合。

例如，压缩器可以包装字节写入器，无需继承文件。压缩器负责帧格式和结束操作，写入器负责目标。压缩器需要说明哪些失败会留下部分输出，以及谁完成各项资源。

## 选择语言机制

- 函数或闭包可以提供小范围计算或操作。
- 字段可以持有或借用具有独立生命周期的协作者。
- Rust trait 描述能力，默认方法可以共享行为。Rust 不提供类实现继承。泛型组合在编译时固定具体类型，trait object 支持动态分发。
- Python protocol 可以为类型检查描述结构能力。类无需继承其实现也能满足它。
- 以子类化为基础的语言或框架，可以用抽象基类提供明确扩展契约。

操作确有需要时再选择运行时替换。泛型组合可以避免动态分发及单独分配。动态协作者可以简化异构集合或运行时选择。

## 有意采用继承

继承适合稳定的行为特化，或框架支持的扩展机制。异常捕获依赖类别关系时，也可以采用异常层次。检查完整的[替换契约](./solid.md)，包含错误、状态及允许的修改。

避免仅为复用辅助方法而继承宽泛行为。禁用继承操作通常暴露了所承诺能力的不匹配。

## 检查包装职责

包装器可以缩小访问范围、转换契约或拥有生命周期，即使其方法很短。复制协作者全部接口的包装器，可能增加维护却收益有限。将直接使用与包装器实际承担的工作比较，参见[深模块](./deep-modules.md)。
