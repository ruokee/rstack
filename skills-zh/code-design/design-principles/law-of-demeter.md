# 迪米特法则

迪米特法则也称最少知识原则，用于限制一个单元掌握另一单元多少内部结构。其面向对象表述倾向于与接收者、参数、新建对象及直接组件交互。用它检查结构耦合。

## 找出外借知识

假设发货代码从订单找到客户，再找到客户当前地址。调用方既了解对象图，也决定了哪个地址代表此次发货。返回订单约定收货目的地的操作，可以拥有这一决定。

追踪结构变化对使用方的影响。修改内部关系迫使无关调用方变化时，判断应由哪项有意义的操作隐藏该关系。长访问链是一条线索。点的数量不构成判据。

## 区分公开结构

透明记录、文档树及传输格式可以有意公开结构。结构属于使用方契约时，直接遍历是合理的。它仍会产生 schema 耦合。多个使用方需要隔离易变外部表示时，可以集中转换一次。

流式 API、迭代器管道及构建器，可以通过稳定操作表达预定顺序。检查每步返回什么，以及是否暴露内部结构。调用链也可以具有完整公开契约。

## 增加有意义的操作

优先用调用方术语表达查询或动作，例如确定发货目的地、预留库存。将遍历及相关规则放在合适的所有者处。有意缩小稳定公开视图的投影也可以有价值。

为每个字段增加转发方法，只是重新分配导航。检查每个方法承担的规则、兼容义务或访问边界。遇到深层 mock 时，同时检查生产调用方是否了解过多，以及检查是否依赖内部实现。
