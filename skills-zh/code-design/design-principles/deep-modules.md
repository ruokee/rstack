# 深模块

John Ousterhout 在《软件设计哲学》中，将深模块描述为通过学习成本较低的接口提供大量有用行为。深度比较获得的能力和调用方所需知识。实现长度难以衡量这两者。

## 计算完整接口

除签名外，还需纳入配置、调用顺序、错误、生命周期及性能。单行网络调用可能要求调用方理解超时、重试、认证及响应归属。简短写法本身不足以说明深度。

解析器可以用稳定的输入、结果及诊断契约，隐藏词法和语法处理。调用方仍需了解接受的语法、输入限制及失败位置。这些是值得公开的使用义务。

## 隐藏决定

选择使用方不应重复处理的决定，例如存储表示、算法、协议转换或协调完成。由一个模块负责，向调用方暴露有意义的操作。契约保持成立时，该决定的变化可以留在局部。

使用方仍需围绕隐藏决定共同协调时，就发生了信息泄漏。例如解释私有存储字段、重复相同错误映射，或手动重现内部初始化顺序。通过[既有代码](../existing-code.md)追踪这些变化。

协议库可以有意公开传输概念，数据记录可以有意公开字段。信息隐藏取决于预期契约。

## 保留必要控制

让常见用法保持简单，同时公开实际调用方需要的控制。批处理、取消、资源完成和错误细节，可能是有用接口的重要部分。隐藏它们可能迫使调用方绕过模块，或重建其内部知识。

例如，报告保存操作可以负责打开、写入及关闭文件，借用写入器的操作可以单独支持现成输出流。两者都可以隐藏格式规则，同时说明自身资源义务。

## 按调用方判断拆分

各部分拥有独立规则、生命周期或使用方时再拆分。拆开协调工作会让每个调用方学习同一顺序时，应将它们放在一起。小函数可以服务任一种设计。函数大小不能决定边界。

薄包装可以通过稳定职责获得价值，例如转换、访问限制或生命周期归属。移除纯改名包装可以减少间接层。完整契约参见[接口](../interfaces.md)，总体复杂度参见 [KISS](./kiss.md)。
