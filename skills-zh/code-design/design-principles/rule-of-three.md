# 三的原则

三的原则提醒我们先从具体情况中学习，再提取共同抽象。常见顺序是直接实现、容忍部分重复，随后根据更多情况重新判断共性。有用证据是这些情况怎样变化，以及因何修改。

## 寻找稳定决定

比较所需行为、前提、失败、归属及修改原因，说明哪项决定应归共同操作，哪些变化仍由调用方处理。第三个实例可能揭示有用区别。三个副本也可能始终属于三项独立策略。

例如，三个导出器可以共享记录投影，转义、缓冲及完成方式各不相同。提取投影可以保留这些独立契约。带格式标志的通用导出器可能掩盖它们。

## 判断提取时机

共同职责已知，接口维护成本低于调用方分别解释规则的成本时，再提取抽象。已确认的金额规则或协议契约可以立即建立统一归属。根据 [DRY](./dry.md) 选择归属形式。

主要理由仍是未来可能出现的变化时，让当前情况保持直接表达，并保留便于日后提取的局部性。出现次数既不是有效边界的前提，也不足以证明某个抽象正确。

## 重审错误抽象

反复出现的调用方专属分支、模式标志和类型逃逸，提示需要检查共同契约。将每个例外追溯到实际要求，拆开独立变化的行为，或用各情况真正共享的决定替换现有抽象。

用 [KISS](./kiss.md) 比较总体复杂度，用 [YAGNI](./yagni.md) 区分当前职责和假想能力。
