# YAGNI

YAGNI 要求推迟需求仍属猜测的能力。围绕已确认行为和已知约束实现，同时保持代码易于修改，让后续需求能在契约明确时得到实现。

## 计算完整成本

Martin Fowler 将推定功能的成本分为四类：

- 构建成本占用原本可以服务当前需求的工作。
- 延迟成本推迟有用成果的交付。
- 持有成本让读者、检查及后续修改持续处理未使用能力。
- 修复成本用于纠正或移除错误预测。

未使用选项仍会增加组合及兼容预期。通用扩展点也会让调用方依赖它选定的变化模型。

## 区分当前结构

协议适配器、资源所有者或稳定的公开契约，可以在只有一个实现时服务当前需求。边界以替换为目的时，第二个实现是相关证据。实现数量本身不足以决定价值。

例如，转换厂商响应以保留领域错误区别，具有当前价值。仅因未来可能增加另一厂商就建立自动发现机制，会增加未确认能力。这是两项不同决定。

正确的错误处理、输入域约束、资源释放及有效行为检查，都服务当前契约。重构可以降低已知修改成本。公开 API 和持久化格式从首次发布起就可能带来昂贵迁移，应按已知义务作出决定。

## 让推迟保持可行

清楚表达规则，集中维护可变化的决定，保留可观察行为的检查。优先直接表达，避免未使用配置。后续需求变得真实时，再按实际调用方及约束推导接口。

用 [KISS](./kiss.md) 简化所需能力。共性不明确时参见[三的原则](./rule-of-three.md)。选择实际扩展边界时参见 [SOLID](./solid.md)。
