# 接口

接口是正确使用模块所需的完整知识。除类型外，还包含行为、错误、顺序、归属及可观察成本。模块可以是函数、对象、包或一组职责完整的操作。

## 先写调用方

从实际操作及其周边生命周期开始，写出能正确完成它的最短调用用法，包含相关失败路径。根据调用方提供、拥有，以及操作后仍然需要的内容推导参数和返回值。

例如，`write_report(out, rows)` 可以借用调用方拥有的流，`save_report(path, rows)` 可以负责打开和关闭文件。后者具有独立的生命周期责任。各自的契约仍需按情况说明编码、格式、部分写入及失败行为。关闭文件负责释放资源。撤销未完成的写入需要另外的机制。

## 定义完整契约

- 描述输入域、单位、身份、顺序及输出保证，说明由谁建立所需前提。
- 调用方处理方式不同时，区分预期领域结果、输入拒绝及基础设施故障，保留诊断所需原因。
- 描述每种失败后的状态：保持原样、部分完成或结果未知。说明操作能否安全重复，以及支撑该性质的机制。
- 区分借用、所有权转移、共享所有权和租约，说明访问何时结束，以及谁完成、取消或释放操作。
- 纳入可观察工作量：阻塞、I/O、分配、复制、保留缓冲、任务创建及结果规模。流式输入搭配全量收集的输出，仍需保留输出。
- 说明调用顺序、配置、线程或任务亲和性及并发保证，指出共享更新在哪项操作生效。
- 使用方依赖公开传输格式、名称、错误及顺序时，将它们视为兼容承诺。

在满足操作要求的前提下缩小契约。真实调用方需要某项可选控制时，再将它放入公开接口。

## 确定保证的实施位置

区分表示能力和实际约束。变体可以将数据关联到状态。私有构造器可以限制创建。检查过的转移可以维护不变量。事务可以按实际隔离规则协调竞争更新。

某些语言的类型注解仅供静态检查。不可变记录按语言规则保护自身字段。任一机制都不应被描述为能够验证任意外部输入或协调独立写入者。

检查所有可达的构造及修改路径，说明存储值的权威性，以及调用方拿到的是活动对象、快照还是标识。这决定读取后作出的判断，在随后的写入时是否仍然有效。

## 选择边界

隐藏调用方不应重复处理的决定，例如协议转换、策略、生命周期或顺序协调。单个实现也可以承担这些职责。适配器专门负责契约转换。接口实现本身可以不涉及转换。

设想移除一层，判断哪些工作随之消失，哪些工作转移到每个调用方。保留能减少总知识负担或让规则获得有效归属的边界。仅改名转发、缺少当前职责的层可以内联。

按所需生命周期和变化选择函数、状态对象、显式会话或扩展接口。依赖注入可以提供有用的替换点。稳定实现细节可以保留在模块内部。

## 检查实际用法

通过拟议公开操作执行成功、相关失败及生命周期场景，对照承诺的后置条件检查状态。静态保证用类型检查验证，效果、清理和成本用运行证据验证。替身需要复现当前场景所依赖的真实语义。
