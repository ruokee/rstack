# 声明式编程

声明式代码描述期望结果、关系或规则，将执行交给求值器。SQL、schema、路由定义、配置及转换表以不同方式采用这种方法。声明的含义由求值器语义决定。

## 理解求值器

选择顺序、优先级、默认值、重复处理、缺失值及错误位置影响规则时，应明确说明。定义何时求值，以及是否产生副作用。声明语言具有清楚模型时，也可以表达决策和顺序。

例如，分层配置需要明确覆盖顺序，路由表需要规定匹配重叠时的处理。静态检查器使用的 schema，与运行时验证器解释的相同形状，提供不同保证。

## 声明结果

下面的独立 SQLite 查询按地区汇总整数分金额，并显式排列结果，返回 `east` 的 170 分及 `west` 的 80 分。引擎选择执行计划。

```sql
WITH sales(region, cents) AS (
    VALUES ('east', 120), ('west', 80), ('east', 50)
)
SELECT region, SUM(cents) AS total_cents
FROM sales
GROUP BY region
ORDER BY region;
```

分组定义汇总，`ORDER BY` 定义输出顺序。查询仍有扫描、聚合及排序等执行成本。成本影响要求时，应检查实际计划。

## 保持声明可检查

表和 schema 能集中展示支持情况，且求值规则稳定时，可以采用声明。固定分发表可以分开选择和执行。在查表边界转换缺失键，再让所选处理器的错误保留自身含义。参见[工厂](../design-patterns/factory.md)。

读者能把结果或错误追溯到负责规则时，声明层才有价值。按机制需要提供有用的源码位置及求值诊断。自定义 DSL 还带来解析、工具及版本管理义务。

## 选择更清楚的显式代码

条件式副作用和不规则生命周期，可能更适合普通控制流。将它们移入配置，会改变复杂度的位置。现成求值器符合契约时可以使用。避免仅为使局部操作可配置就自建求值器。

执行顺序参见[命令式](./imperative.md)，表示参见[数据建模](./data-modeling.md)，声明转移参见[状态机](./state-machine.md)。
