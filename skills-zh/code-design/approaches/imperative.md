# 命令式编程

命令式代码说明计算步骤及局部状态怎样变化，过程式分解将步骤组织为具名操作。它适合有序副作用、资源获取、启动、命令处理器及小型脚本。

## 明确顺序

对每一步说明输入、效果、结果及失败状态。例如，按配置执行的作业可能依次解析输入、解释设置、获取客户端、处理记录及完成输出。顺序所有者需要决定部分记录已经写入后，处理失败应如何结束。

顺序调用建立当前调用方的执行次序。它不能让副作用成为原子操作。写入可能产生部分输出，远程调用可能留下未知结果。事务及恢复决定应归拥有这些效果的操作。

## 保持状态局部

用局部变量和显式参数表达变化，为共享可变状态安排归属及同步契约。将同一个可变上下文传遍全部过程，也可能像全局变量一样隐藏依赖。

纯算法可以使用循环和私有临时状态修改。命令式语法描述计算方式，纯度描述调用方可以观察到什么。这两项性质可以同时存在。

## 提取有效操作

阶段拥有独立规则、输入输出契约、资源生命周期或可复用目的时，再拆分顺序。让调用方在一致的详细程度上表达操作。辅助函数应减少所需知识或隔离决定。

避免仅为命名执行位置，就提取每个短代码块。额外调用会让操作更难追踪时，清楚的局部处理可以内联。重复标志或无关分支，可能说明多项操作被合并到同一个入口。

## 按需要分离决策

定价规则或资格判断通常可以接收普通值，周边过程负责 I/O 和持久化。这样可以独立于基础设施直接检查规则。参见[函数式核心](./functional-core.md)。

字节复制操作可能几乎没有独立策略，有意义的工作就是副作用顺序本身。根据[资源生命周期](./resource-lifecycle.md)清楚表达清理、失败报告及完成。中间值需要更明确契约时，参见[数据建模](./data-modeling.md)。
