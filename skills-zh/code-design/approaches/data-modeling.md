# 数据建模

数据建模定义含义、身份、合法形状及转换。从数据必须支持的操作和不变量出发。序列化便利是其中一项约束。

## 选择逻辑形状

- 共同存在且取值独立的字段使用记录。
- 必需数据不同的互斥情况使用变体。状态标签从变体推导，避免另存可独立修改的标签。
- 混淆标识或单位会违反真实契约时，使用不同类型。类型别名可以改善术语，同时保留原有底层类型。newtype 可以约束区别。
- 区分存储的权威来源与快照、投影或派生值。保留派生数据时，定义它怎样保持更新。
- 在负责相应契约的边界说明数值范围、精度、舍入及缺失值语义。

例如，支付可以处于待处理、带凭据的已支付，或带原因的失败状态。封闭和类型将载荷关联到对应情况。多个独立布尔值和可选字段会容纳契约从未使用的组合。

## 验证领域规则

形状正确的值仍可能违反领域规则。浮点数可能非有限，日期区间可能倒置，标识可能指向缺失记录。由掌握足够信息的所有者约束各项所需性质。

区分静态保证、运行时解析、检查过的构造、受控修改及调用方前提。Rust 枚举在编译时约束变体。公开变体仍允许直接构造。Python 注解支持静态检查。它不会验证任意运行时输入。

不可变值可以通过限制修改，维持已建立的不变量。嵌套可变对象及共享别名仍需要自己的策略。单独的不可变性不能建立构造时的合法性。

从存储恢复观察到的状态，以及授权转入该状态，属于不同契约。允许的历史重要时，参见[状态机](./state-machine.md)。

## 明确转换

说明解析、验证、规范化、计算及序列化各阶段产生的表示。共享一项有用契约时可以合并阶段。后续使用方需要区分含义时，应保留该区别。

金额输入转换为整数单位前，需要定义币种、接受的十进制语法、舍入位置及溢出行为。逐行舍入与汇总后舍入，可能得到不同结果。避免让运行时偶然采用的数值默认行为决定业务规则。

## 按访问方式选择物理布局

逻辑形状和物理布局是不同决定。结构体数组将每条记录的字段放在一起。数组结构体可能改善只扫描少数字段的工作，同时增加并行数组协调及记录更新成本。

检查实际表示。Rust `Vec<Record>` 连续存储记录，记录拥有的字符串仍可能指向独立分配。Python list 保存对象引用。仅将字典改为带类型记录，不足以说明缓存局部性或内存密度。

测量代表性访问、分配、复制及保留量。生命周期允许时借用数据，归属变化时移动拥有的值。大型输入采用有界批次，根据归属契约判断就地修改。

受控状态参见[面向对象](./object-oriented.md)，显式转换参见[函数式核心](./functional-core.md)。
