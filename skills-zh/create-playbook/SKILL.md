# 创建流程

创建或维护说明一类工作如何推进的可复用文档。Playbook 通过必要依赖、选择、反馈、交接和完成方式衔接活动。你是执行这项工作的 Agent。文档详略与实际需要相称。

## 调查工作

读取所需成果、相关规则、已有流程、工作记录及代表性产物。确定这类工作的起点、终点，以及流程需要解决的困难。沿用有效决定。

按实际起点处理：

- 提炼已有实践时，追踪发生了什么及其原因。将可复用的判断与当次值、偶然顺序分开，保留做法适用的条件。
- 面向新需求时，从预期结果、可用能力和约束推导必要活动。设计假设、实际历史和已确认要求分别保存。
- 维护流程时，读取当前正文和反馈，先定位受影响的判断、活动或使用路径。

工作需要专业方法时再读取。系统搜集证据使用 `research`，待解的推理问题使用 `thinking-method`，领域含义及规则使用 `domain-driven-design`。`reflect` 可以从工作记录中提供改进线索，`improve` 支持围绕约定改进目标进行比较。

## 形成使用约定

调查使用者、适用范围、维护归属，以及读者当前怎样找到方法。读取现有存放规则、目录、导航和权威项目材料。已有适用约定直接采用。

按维护归属选择正文位置。私有流程沿用已有明确位置。默认位置如下：

- 个人流程：`~/.agents/playbooks/`。
- 项目或工作区流程：相应根目录的 `.agents/playbooks/`。
- rstack 公共流程：相对本入口的 `../use-rstack/playbooks/` 目录。维护遵循该仓库的授权。

首次保存流程时建立所需私有目录，保持其独立于已安装的 Skill 包。rstack 的发布更新公共内容，私有维护者负责私有更新。

决定后续请求如何找到正文。核对可得事实后，与用户解决影响结果的缺口和取舍，例如归属不清、范围或发现入口。将约定保存到当前授权材料中。项目命令、对象判据及执行者安排从当前环境取得。

## 设计活动

从预期成果倒推所需输入及判断。纳入活动的依据是它能推进成果或解决真实的不确定性。按实际依赖连接活动。

在影响使用的位置明确以下关系：

- 什么输入允许活动开始，下一活动接收什么结果。
- 哪些事实决定分支或要求更换方法。
- 哪些判断由人作出，工作在哪里等待。
- 关键交接由谁接收，接收什么结果、上下文、候选身份及证据。
- 新信息、失败或目标变化如何影响剩余工作及已有结果。
- 什么结果结束这类工作，暂停后接续需要保留什么。

专业方法保留在相应 Skill 中，项目事实保留在权威材料中。按名称引用 Skill 并说明读取条件。例如，建立或修改验证方法时读取 `create-verification`，执行已有方法时遵循其说明。实际设计问题需要原型或类型设计时，使用 `prototype` 或 `type-driven-design`。用户显式请求状态建模、交错检查或模型维护时，使用 `statechart`。

## 编写流程

使用普通 Markdown，让读者能从实际入口开始工作。说明适用条件、起始输入、必要活动、选择、反馈、交接及完成条件。保留理解判断和读取必要参考所需的上下文。

单文件流程保存为 `<name>.md`。需要单列分支说明或配套文件时，以 `<name>/playbook.md` 为入口，用相对路径链接材料并说明何时读取。导航直接链接入口文件。标题、字段、步骤数量、角色和脚本按该流程选择。`writing-for-agents` 帮助组织 Agent 指令及读取指针，`wellsaid` 帮助整理表达。

将稳定的流程判断与当前任务的具体值、进展和权限分开。引用权威项目事实，让读者取得适用命令及判据。在权限影响使用的位置说明所需授权。设计流程的请求具有自己的完成条件，运行流程中的业务操作需要相应执行范围和权限。

### 维护对应材料

修改前先判断反馈归属。通用方法变化放在相应 Skill，流程变化放在该 playbook，项目事实放在项目资料，当次调整放在当前安排。各位置遵循其修改权限。

改名、移动或改变流程要求时，追踪实际导航、入站引用及使用者。在范围内共同更新正文和受影响的连接。已有任务保留自己的候选身份、有效决定和有效结果，调整其安排前先判断流程变化对该任务的影响。

个性化改写公共流程时，创建私有版本，保留判断后续变化所需的来源信息。版本记录采用环境已有方式。私有维护者决定如何吸收公共内容的后续变化，公共更新维护公共内容。

## 接入发现位置

将正文及必要参考保存到约定位置。现有发现入口已经足够时，直接接入。单份流程可以只用一个指针，数量或选择需要确实要求时再增加轻量导航。

多个流程提供名称、适用情形及正文路径。所在导航可以统一说明维护来源、归属及范围。名称与来源、正文身份分别表达。公共和私有流程同名时，保留明确选用或既有替代关系。环境确有需要时再形成来源优先约定。

将新导航链接到读者已经能够发现的位置。`use-rstack` 可以通过该指针取得并使用结果，读者也可以按既有工作约定直接使用流程。

## 检查交付

从真实发现入口沿流程走读，确认读者能够找到并读取预期正文和必要参考。检查活动输入输出、分支条件、反馈、交接、权限边界、暂停接续及完成方式。改名或移动后沿受影响链接检查。

分别记录文档检查和执行观察。按当前检查约定及权限实际使用流程，保存实际使用的具体输入、条件、输出和发现。在范围内修复缺陷，复查受影响路径。

交付流程位置、发现入口、适用范围、维护归属、已做检查及使用所需条件。写入成功、可发现、实际使用有效及本次创建请求完成，分别依据相应证据判断。
