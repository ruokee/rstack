# Failure

Trace how a concrete loss of capability changes the promised system result. Failure can be equipment loss, staff absence, supply interruption, a missed handoff, stale information, exhausted resources, or failed recovery.

## Follow propagation

Name the initiating event, how it becomes visible, the dependent work, the remaining capacity, and the resulting unmet obligation. Distinguish the failed part from the full affected area. A shared utility, supplier, approval authority, or work record can defeat apparently independent alternatives.

Constructed repair example: two repair benches share one calibration device. Losing that device prevents both benches from releasing verified work. Adding another bench leaves the common dependency. An alternative calibration route provides useful redundancy only if it has the required capability, capacity, availability, and acceptance authority.

Consider delayed and incorrect results as well as complete stoppage. Old parts information can schedule work that cannot start. An absent acknowledgment can leave both parties assuming the other owns the case. Diagnose the actual initiating cause when that is part of the task; architecture evaluation can separately identify the propagation mechanism.

## Compare responses

Isolation limits the affected work or resources, with a cost in separate capacity and coordination. Standby capacity helps when it is independent of the initiating cause and can take over in time. Deferral needs a waiting location, a promise, and an owner. Reduced service needs an explicitly acceptable result. Manual takeover needs authority, information, trained people, and enough capacity for the expected duration. Stopping can protect irreversible obligations when proceeding would create unacceptable harm.

Select the response by the result it preserves and the cost it accepts. A nominal backup whose staff or equipment is already fully occupied may have little takeover capacity. Switching all work to it can reproduce overload.

## Recover from the actual state

Before repeating work, determine what has already completed and what effects are irreversible. If the result is unknown, assign a reconciliation action. A second dispatch, purchase, or repair can have a real cost even when the first response is missing.

State who takes responsibility, the current authoritative record, required resources, takeover conditions, and the evidence of restored service. Include unfinished work, duplicated assignments, and accumulated backlog. Recovery may initially consume capacity faster than ordinary operation.

Define acceptable data or record loss and acceptable restoration time from the actual obligation. A spare device addresses device failure. A recoverable record and a person able to use it address continuity of work. Match recovery evidence to the failure scenario, including the common dependency where relevant.

For a missing part, the repair case should remain owned and visible. Its owner confirms the new supply plan, updates the promise, and returns ready work to scheduling. Recovery is complete when the required result and outstanding obligations are accounted for.
