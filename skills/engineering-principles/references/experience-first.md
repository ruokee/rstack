# Experience first

Implementation choices distribute effort between the author and everyone who uses the result. Evaluate that distribution through the consumer's complete task. The consumer may be an end user, API caller, reader, or maintainer.

A command that starts a long export needs to communicate how the caller obtains the finished result. Returning an opaque job identifier may be adequate for an automation client with a status API. An interactive user may need a usable progress view and a clear destination. Choose feedback from the actual usage contract.

Follow the task from its starting point through decisions, errors, and completion. Identify where users must guess, repeat work, or reconstruct information the implementation already knows. For documents, examine whether prerequisites and next actions appear where readers need them.

Prioritize these costs when they conflict with implementation convenience. Preserve confirmed functionality and constraints. Scope reductions and changes in product direction belong to the authorized decision-maker.

Use a disposable prototype when observation can resolve a material uncertainty about the experience. An established choice can proceed directly. The aim is a usable complete result for the agreed task.
