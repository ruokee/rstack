# Subtract before add

An apparent need for another mechanism can come from a rule that has outlived its purpose. Check whether the desired behavior becomes possible when that rule is removed.

For example, a command has two switches because it once supported two execution engines. Only one engine remains, and both switches now control the same choice. Adding precedence rules would preserve contradictory combinations. Retiring the redundant switch can resolve the ambiguity at its source.

Establish what still consumes the candidate for removal and which contract it protects. Remove the obsolete part within the authorized change, including references that would otherwise point to it. Judge the remaining requirement against the resulting structure.

The same reasoning applies to duplicated state, forwarding wrappers, unused branches, and repeated document instructions. Keep conditions and navigation that readers still need. Input checks protecting a real contract retain their purpose.

Subtraction is sufficient when the simpler result meets the goal. Add the remaining capability only where a requirement is still unmet.
